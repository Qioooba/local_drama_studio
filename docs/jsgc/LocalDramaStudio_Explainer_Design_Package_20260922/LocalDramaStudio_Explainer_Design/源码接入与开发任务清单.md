## 6 LLM提示与输出约束

每个operation都拆成可信系统指令、版本化任务说明、结构化上下文和不可信来源文本；禁止把抓取网页混进系统提示。JSON schema使用additionalProperties=false，校验失败最多有限修复一次格式，再失败保存原始输出及错误，不用正则“猜”出一个通过结果。

| 操作 | 必需输入 | 输出约束 | 失败条件 |
|---|---|---|---|
| 事实提取 | source_id、已存source spans、实体表 | claim必须给存在的span引用、时间精度、事实/解释类别 | 引用不存在或超出正文、凭空增加数字 |
| 冲突核验 | 同一claim候选及独立来源链 | SUPPORTED/DISPUTED/UNVERIFIED、具体证据和分歧 | 仅以来源数量或模型自评分判断 |
| 讲稿 | 锁定事实、受众、问题、章节、字数预算 | 段落ID、claim映射、过渡语；不能捏造真实对白 | 改变否定、结果、日期、人名或新增因果 |
| 翻译 | 原段、术语表、事实、语气 | canonical_segment映射、localization notes、实体数字对照 | 省掉not/未/可能，数字单位不一致 |
| 分镜 | 讲稿、实测语音、实体/风格、能力 | 可渲染类型、视觉焦点、参考、运动、frame预算 | 不支持的首尾输入、动作不可能或无关画面 |
| 提示编译 | beat、身份/场景/道具、当前状态 | 有序参考映射、构图、动作、光线，历史事实不新增 | 引用归属不明、把艺术设定写成史料 |
| 视觉审查 | 参考、候选帧、镜头事实/意图 | issue类型、具体帧、证据、UNKNOWN | 只有“8分”而没有判断对象/理由 |

若需要生成出镜人的三视图，不让写稿模型直接为全片每个人重复输出长prompt。由身份资产计划先去重，再按需求派生，后续镜头引用其稳定ID。

## 7 幂等 事务 与运行时对账

写操作遵循以下顺序：验证对象与revision → 规范化payload/hash → 在短事务内检查idempotency key → 写命令/任务快照与outbox → 提交事务 → worker执行外部任务。外部生成耗时不进入SQLite事务。

同key同payload返回原结果；同key不同payload返回409。外部provider接受请求但本端超时，记录provider_acceptance_unknown，保存可得到的job/session标识并查询；不能由超时自动新建创作variant。重复worker回调用attempt id和fencing token拒绝过期提交。

文件先写工作目录临时对象，探测/哈希成功后原子迁移到受控产物位置；数据库登记失败的孤立文件进quarantine/恢复对账。DB已SUCCESS而文件缺失/哈希变化时改为可见完整性故障，不能静默重新生成替换相同media version。

修改源文本只生成新revision；冻结render manifest读取指定revision，不读CURRENT/LATEST。发布包先保存全部文件清单与hash，再标ready；ZIP自身也计算hash。来源/授权未通过的包可保留预览，但不能改名当全球发布已完成。

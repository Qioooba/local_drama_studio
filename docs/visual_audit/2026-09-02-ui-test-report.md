# Local Drama Studio UI 全量视觉与交互测试报告

## 1. 测试结论

本轮完成了 29 个页面/兼容路由在 5 种分辨率下的截图与指标采集，共覆盖 145 个页面状态，生成 290 张页面截图（viewport 与 full-page）。同时在桌面端深色主题下对 29 个页面执行了按钮、文本输入框、下拉框和 Tab 的自动化初测。

总体结论：页面在响应式布局上没有发现横向溢出，基础控件可访问性命名整体完整；但存在主题能力缺失、深浅色 token 混用、部分文字对比度不足、44px 触控尺寸未达标、缩略图加载异常，以及一次本地服务契约接口 500 导致兼容性门禁遮挡页面的问题。建议修复高优先级视觉和运行时稳定性问题后，再进行第二轮逐控件回归。

## 4. 主要问题

### P1 — 本地服务契约检查偶发 HTTP 500，导致兼容性门禁遮挡页面

截图采集过程中，`/api/v1/system/contract` 曾出现 HTTP 500，页面显示“无法核对本地服务版本”，并提供“重新检测服务/载入最新界面”操作。后续直接重试接口恢复 HTTP 200，说明更像是瞬时稳定性问题，但当前门禁对瞬时失败的容错不足。

影响：系统任务、导演台等页面可能被错误状态卡住，影响真实验收和截图审核。

建议：增加有限次数重试与退避；区分网络失败、服务未启动和契约不兼容；保留页面主体并在局部展示告警，避免一次瞬时 500 覆盖整个工作区。

证据：`dark/mobile/25-system-jobs-viewport.png`、`dark/mobile/17-shot-studio-viewport.png`。

### P1 — 当前未发现浅色主题实现

当前样式以 `color-scheme: dark` 为主，未发现 `data-theme`、`prefers-color-scheme` 或主题切换入口。因此本轮只能完成深色主题截图，无法完成“深色/浅色主题全量对照”。

影响：如果产品验收要求支持多主题，这是功能缺口；如果产品明确为深色专用，则应在验收标准中明确记录，避免将“主题覆盖”误认为已完成。

建议：使用语义化颜色 token 增加浅色主题，并对 29×5 矩阵至少补跑浅色主题；同时检查系统主题跟随和主题切换后的持久化。

### P1 — 交付设置页出现深浅色 token 混用

交付设置页存在浅色薄荷色表面 `rgb(237,249,244)`，但叠加了深色界面的文字颜色。自动对比度检测命中：白色文字与该表面约 1.00:1，灰色文字约 2.33:1，均明显不足。

影响：品牌/项目母版区域的标题和说明在部分背景下难以阅读。

建议：为浅色 surface 使用专用深色前景 token，或将该区域恢复为完整深色 surface；补测正文至少 4.5:1、大字号至少 3:1 的对比度要求。

### P1 — 大量可交互控件低于 44px 触控目标

5 种分辨率均检测到控件尺寸命中，单个视口约 126–219 次。现有基础样式中部分 `button/select/textarea/summary` 的最小高度为 40px，低于移动端建议的 44px 触控目标。

影响：移动端和横屏设备上按钮、筛选器、设置项更容易误触，尤其是密集的配置面板。

建议：移动端将主要可交互控件统一提升到至少 44×44px；图标按钮补足点击区域；对紧凑型桌面控件区分视觉高度与实际 hit area，并按组件级别回归。

### P2 — 多处辅助/状态文字对比度不足

检测到以下代表性命中：故事页提示文字约 2.65:1；能力页“可执行/预检通过”状态文字约 1.64:1；导演台“1 个候选 · 查看”约 4.01:1；任务页元信息约 4.05:1。后两项接近但仍低于普通正文 4.5:1 标准。

建议：不要直接复用强调色作为文字前景；为状态文字、次要元信息和浅色 pill 分别建立语义 token，并在深色/浅色背景上分别校验。

### P2 — 工作台项目缩略图存在加载异常

在工作台页面的 Laptop、Tablet、Mobile landscape 截图采集期间，发现以下缩略图请求异常：

`/api/v1/media-versions/f956d361-bb92-42c9-91dd-2b5a3900ad83/thumbnail?size=small&frame=poster`

建议：核查对应媒体版本的缩略图生成与 API 返回；前端增加稳定的占位图、错误态和重试，避免破图图标直接出现在项目列表。

## 5. 交互初测结果

本轮按“可安全执行”的策略点击可见按钮、填充文本框、选择有足够选项的下拉框并切换 Tab。删除、清空、重置、保存、创建、生成、提交、发布、导入、上传等可能改变业务数据的操作默认跳过。

| 项目 | 结果 |
|---|---:|
| 按钮总数 | 140 |
| 已点击按钮 | 88 |
| 因禁用或可能改数据而跳过按钮 | 49 |
| 按钮脚本失败 | 3 |
| 文本输入框成功 | 16 |
| 文本输入框值规范化/不一致 | 4 |
| 文本输入框失败 | 0 |
| 下拉框成功 | 26 |
| 下拉框脚本失败 | 20 |
| Tab 成功 | 10/10 |

3 个按钮失败和 20 个下拉框失败主要表现为自动化脚本在前序交互改变 DOM 后仍使用旧索引定位，属于测试脚本定位漂移，尚未认定为产品缺陷。需要第二轮按按钮文本、label、关联 id 或稳定测试标识重测。

4 个输入框值不一致主要是输入值被业务规则规范化（例如数量上限、秒数格式化）或密码字段不回显，不属于输入失败；应在第二轮增加规则断言。

## 6. 已通过或未发现的问题

- 145 个页面状态均未检测到横向页面溢出。
- 未发现缺少可访问名称的图标按钮。
- 未发现未关联 label 的文本输入框。
- Tab 交互初测 10/10 成功。
- 页面整体响应式结构在桌面、平板、移动端和横屏下能够切换为单列/堆叠布局。

## 7. 未覆盖与复测建议

- 浅色主题：当前应用未提供可执行的浅色主题入口，需补齐实现或明确产品范围。
- 减少动效（`prefers-reduced-motion`）：本轮未单独切换系统设置验证。
- 破坏性操作：未执行删除、清空、重置、保存、生成、发布、导入、上传等真实写入操作。
- 交互第二轮：修正自动化定位策略后，逐页按稳定标识重测 20 个下拉框和 3 个按钮，并对输入规范化规则写成断言。
- 视觉复核：优先复核交付设置页的浅色区域、移动端密集控件、工作台缩略图和所有裁切检测命中项。

LocalDramaStudio V2 visual audit — 2026-08-21

Scope
- Runtime: http://127.0.0.1:5173 with API http://127.0.0.1:3210.
- Primary viewport: 1280x720. Director Desk additionally sampled at 1024x768, 1440x900 and 1920x1080.
- Fixture: project e5eaa01d-d39a-4a63-acbf-026da30b46e7, episode d4db1033-9517-4bd0-958d-4228e0abead1, 22 shots.
- Evidence: docs/research/assets/current-v2-2026-08-21/.
- 22 full-page originals were split into 80 720px-high review segments. manifest.json records exact sizes; contact-sheet-01.jpg through contact-sheet-05.jpg are the thumbnail review surfaces.
- Full-page capture can repeat sticky chrome at stitch boundaries. Repeated headers inside contact sheets are capture behavior unless independently confirmed in a normal viewport screenshot.

Release-blocking runtime findings

P0-1 Episode Plan does not render.
- Route: /projects/{projectId}/episodes/{episodeId}/plan.
- Visible result after a 2.2s settle: the React Router development error page, not a product error state.
- Runtime error: TypeError: drafts.data?.find is not a function.
- Stack origin: apps/web/src/features/episode-plan-v2/SelectedBeatReplanPanel.tsx, selectedDraft lookup.
- The exact root cause is now code-proven: AIDraftReviewPanel.tsx and SelectedBeatReplanPanel.tsx share ["script-breakdown-drafts", projectId]. The first query caches the endpoint envelope {items,...}; beatReplanApi.ts unwraps the same resource to an array for the second query. TanStack Query reuses the envelope and SelectedBeatReplanPanel calls .find on it.
- Required gate: one semantic key factory and one canonical envelope for this resource; derive arrays with select. Add a shared-QueryClient composition test. No V2 route may expose the router developer error page; schema-parse API responses and show a recoverable region error with request ID and retry.

P0-2 Director Desk cannot expose all primary regions at ordinary desktop widths.
- At 1280x720 the document is 1670px wide. Measured regions: global chrome/sidebar consumes roughly 233px; Shot Navigator starts x=233, width=238; Media Stage starts x=471, width=1170; Inspector starts x=1641, width=330.
- The Inspector begins beyond the reachable normal viewport. The page has horizontal scroll, the Shot Navigator filter/actions have their own horizontal overflow, and Takes extend beyond the right edge.
- At 1440x900 the Inspector is still not visible in the normal viewport.
- At 1920x1080 the Inspector remains clipped beyond the Media Stage instead of sharing the available width.
- At 1024x768 the global navigation becomes a horizontally scrolling top row and the Director workspace also overflows; this is not an adaptive editor layout.
- Required gate: no page-level horizontal scroll at 1024/1280/1440/1920; all three Director regions must be reachable without horizontal panning, using an icon rail/focus mode and responsive drawers where necessary.

P0-3 Director can open Manual Generation on the wrong shot.
- DirectorDeskPage currently builds generation?shot=<id>, while GenerationPage only reads the optional path parameter /generation/:shotId and otherwise selects the first shot.
- From any non-first shot, the visible URL contains the intended query but the generation form targets the first shot. This can waste GPU time and attach a new Variant/Job to the wrong business object.
- Required gate: typed path builders; an invalid or absent shot cannot silently become a writable first-shot selection; URL, selection, preflight, request payload and persisted Job shot_id must agree.

P0-4 Generation capability names and resolution paths are split.
- New preferences use LLM_STORY_PARSE / VIDEO_I2V; legacy Profile/worker paths use SCRIPT_BREAKDOWN_LLM / I2V / T2V; Director mixes IMAGE_GENERATION / I2V / VIDEO_FIRST_LAST_FRAME.
- Required gate: a canonical capability authority, explicit alias/backfill report, and one shared resolver used by settings, Director, manual generation, episode run and worker. No silent fallback.

P0-5 Long-page aggregation is still the dominant V2 pattern.
- Project Operations: 7284px / 11 review segments.
- Episode Run: 4815px / 7 segments.
- Episode Review: 4376px / 7 segments.
- Manual Generation: 4356px / 7 segments.
- Timeline: 4255px / 6 segments.
- Models: 3407px / 5 segments.
- Story Workspace and Audio: 4 segments each.
- The migration improved styling and route separation, but several routes still concatenate legacy-grade panels vertically. This preserves implementation inventory, not user task flow.
- Required gate: production workspaces are viewport-contained. A page gets one primary task, one primary CTA and bounded internal panels. Secondary configuration moves into tabs, drawers, dialogs or dedicated subroutes with deep links.

Cross-page strengths to preserve
- The dark persistent chrome plus warm low-glare work surface is distinctive and appropriate for long production sessions.
- Project entry has a clear next action and the Project Home goal cards are much easier to understand than a technical dashboard.
- Selected and approved are generally kept semantically separate.
- V2 route structure now follows project and episode context and is deep-linkable.
- Advanced Canvas and Media Lab are visibly separated from the normal linear flow.
- Production concepts are real domain concepts: immutable revisions, preflight, local runtime, QC, frame bridge, candidates, review and frozen timeline.

Cross-page UX problems
- Navigation overload: when an episode is active, the persistent navigation can expose project creation pages, three tools, eight episode stages and system destinations at once. At 1024 it becomes a horizontal scroll strip. Users must parse the whole product before completing one task.
- Hierarchy overload: page title, eyebrow, status pills, multiple panel headings and technical labels frequently compete at the same visual weight.
- Mixed language: English implementation terms (Recipe provenance, COMPOSE, LOCAL_ONLY, Profile, Variant, Disposition, plan/diff/apply) appear in primary creator flows. Keep them in advanced/audit details; use Chinese task language in primary UI.
- Global environment warning is always visually strong. Healthy state should be quiet; blocking state should explain the affected action locally.
- Forms expose too many low-frequency fields at once. Advanced values need progressive disclosure and inheritance summaries.
- Empty trailing space in cropped long pages is expected padding, but the real pages still require several screenfuls of uninterrupted vertical reading.
- System/admin concepts remain mixed with project creative tasks, particularly Project Operations.

Page-by-page review and target disposition

00 Projects — 1280x720, 1 segment
- Good: clear search/filter, two recent-project cards, one dominant project action, no content overload.
- Improve: translate “待配置 / 修订” into creator-facing progress; show last meaningful activity and next blocked reason; keep machine health quiet unless blocking.
- Disposition: retain as top-level entry, polish rather than redesign.

01 Project Home — 1265x1086, 2 segments
- Good: four goal-oriented entry cards and an episode list make “what next?” concrete.
- Problem: persistent sidebar already lists almost every project and tool route; episode rows repeat three actions per episode.
- Target: keep the four entry modes; episode rows get one primary “继续” plus overflow actions; add a compact production-progress strip instead of exposing every stage in the global sidebar.

02 Story Workspace — 1265x2170, 4 segments
- Good: the four conceptual steps and staged preview/commit semantics are correct.
- Problem: all steps are physically stacked on one document; import, review, asset resolution and story-bible maintenance compete vertically.
- Target: viewport workspace with a four-step rail, source/editor center and evidence/review inspector. Keep autosaved draft and explicit commit. Each step owns a URL state.

03 Asset Bible — 1280x720, 1 segment in empty fixture

- Target: left entity/state navigator, central visual/reference board, right constraints/voice/usage inspector. Three-view, expression, outfit and episode state are first-class slots, not a long form.

Target navigation synthesis
- Global rail: Projects, Search/Commands, Jobs, Local Runtime; Settings/Diagnostics in an overflow/system group.
- Project context header: project/season/episode breadcrumb, production status, effective model/QC summary.
- Project-level contextual tabs: Overview, Story, Asset Bible, Production Settings; Canvas/Lab in Tools.
- Episode stage rail: Plan → Direct → Review → Audio → Timeline → Deliver. Episode Run is a prominent mode/action, not another equal navigation item.
- Manual Generation is entered from the selected shot and remains deep-linked; it is not a permanent peer to every episode stage.
- Director focus mode collapses global chrome automatically but retains a visible path back and the command palette.

Design-system implications
- Preserve the current hybrid dark-chrome/warm-work-surface system. Do not switch to generic pink entertainment UI, glassmorphism or decorative gradients.
- Use one SVG outline icon family; replace text arrows, multiplication symbols and glyph-based structural controls.
- Maintain 4px spacing, 40px desktop controls and 44px icon hit targets.
- All production pages must meet 1024, 1280, 1440 and 1920 no-horizontal-scroll gates; media workbench panels may internally scroll only where clearly bounded.
- Use progressive disclosure, explicit human gates, fixed-size loading skeletons, localized recovery and visible autosave/conflict state.

# AI 漫剧创作工作台：输入控件与自动化优化深度分析报告

> **编制日期**：2026-08-24  
> **文档定位**：面向 AI 漫剧/短剧创作者体验（UX）的交互改造与系统自动化升级规划。  
> **核心原则**：
> 1. **消除技术暴露**：创作者不应接触 `UUID/ID`、`微秒时间戳 (_us)`、`裸 JSON 数据结构` 等底层细节。
> 2. **标准化提示词词典**：情绪、微表情、视线、构图等字段从自由文本框升级为标准化预设/下拉/标签，稳定模型输出质量。
> 3. **上下文智能推导**：充分利用已有剧本、场次、角色、场景上下文，让系统后台自动填充与继承，减少 80% 的重复打字。

---

## 一、 系统输入控件全局诊断与改造总览

| 模块 | 当前不合理表现 | 改造方案（下拉 / 单选 / 标签 / 自动化） | 自动化推导 / 后台实现机制 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| **导演工作台** | 情绪自由手输文本框 | 常用情绪胶囊标签组 + 强度滑块 (0~100%) | 后台根据剧本动作与对白自动预填充默认情绪 | **P0 (极高)** |
| **导演工作台** | 面部微表情自由手输文本框 | 漫剧常用微表情下拉 / 预设多选 | 后台根据台词情绪自动推导微表情建议 | **P0 (极高)** |
| **导演工作台** | 视线方向自由手输文本框 | 影视视线单选按钮组（左/右/直视/仰/俯等） | 默认直视镜头或根据 2D/3D 站位自动计算朝向 | **P0 (极高)** |
| **导演工作台** | 场景环境多行文本框每镜手写 | 自动继承关联场景资产 + 差异补充文本 | 后台自动将关联场景的“日景/夜景/空间/氛围”带入 | **P0 (极高)** |
| **导演工作台** | 前后镜连续性多行文本框每镜手写 | 连续性继承开关 + 关键状态勾选 | 后台自动继承上一镜的角色服装、伤势及尾帧状态 | **P0 (极高)** |
| **2D/3D 站位板** | 角色名自由手输文本框 | 出场角色下拉选择框 | 自动加载本集/本场次已关联的角色资产列表 | **P0 (极高)** |
| **生成控制面板** | 分时/表演时间输入微秒 (`time_us`) | 秒级 (s) 小数输入框 / 时间线区间滑块 | 前端输入秒，后台自动 `time_us = Math.round(s * 1000000)` | **P0 (极高)** |
| **运动控制面板** | 运动笔刷手写坐标 JSON 数组 | 画布涂抹 / 箭头轨迹绘制交互 | 用户在参考图上画箭头，前端 Canvas 自动采集坐标点 | **P0 (极高)** |
| **生成与后处理** | 手输 `maskMediaVersionId` 等 UUID | 素材缩略图选择器 (MediaPicker) / 下拉列表 | 系统读取当前项目已验证媒体列表供可视化挑选 | **P1 (高)** |
| **分镜批量板** | 批量分镜类型手输 (`batchShotType`) | 标准景别下拉框（中景/近景/特写/大全景等） | 提取系统全局共享的景别枚举常量 | **P1 (高)** |
| **分镜批量板** | 复制/拆分镜头编号手动输入 | 系统规则自动命名 (`原编号_COPY` / `-A` / `-B`) | 自动顺延镜号重排，提供拆分时长比例滑块 | **P1 (高)** |
| **故事长文导入** | 手动输入段落起始/结束数字 | 原文段落鼠标划选 / 章节点击选择 | 后台长文解析时自动识别章节并标记段落起止 | **P1 (高)** |
| **故事创作资料** | 手动输入英文大写代码 (`CHAR_HERO`) | 中文名称输入，自动生成英文 Slug / Code | 标题输入“林默”，后台自动转拼音/大写 `CHAR_LINMO` | **P2 (中)** |
| **声音与 TTS** | 发音映射手输 JSON (`{"词":"拼音"}`) | 结构化多行发音校对表格 | 前端表格编辑，后台自动组装为发音映射 JSON | **P2 (中)** |
| **模型与能力** | 4 个裸 JSON 文本域（输入/输出/资源） | 常用能力预设卡片 + 可视化表单 | 预置主流工作流模板，裸 JSON 收折于高级调试模式 | **P2 (中)** |

## 二、 逐模块深度剖析与落地设计

---

### 1. 导演工作台与单镜意图 (`DirectorIntentEditor.tsx` / `StagingBoard.tsx`)

#### (1) 表演情绪 (`performance.emotion`)
* **现状问题**：使用 `<input placeholder="克制、慌张、决绝…" />`。漫剧用户输入口语化词汇（如“心里发虚”、“七上八下”）时，底层生图/生视频模型无法准确理解，导致画面崩坏。
* **改造设计**：
  * **预设标签库**：提供漫剧高频情绪标签胶囊（喜悦、愤怒、悲伤、恐惧、冷峻、慌乱、震惊、狠厉、温柔、阴险、决绝、崩溃、疲惫、傲慢）。
  * **强度滑块**：保留 `intensity` 百分比滑块（默认 50%）。
  * **后台自动推导**：用户在剧本拆解阶段，LLM 已经分析了该镜头的对白和角色心理，系统自动将提取到的情绪预选为默认标签，用户仅需一键确认或点选微调。

#### (2) 面部微表情 (`performance.facial_action`)
* **现状问题**：使用单行自由文本框。
* **改造设计**：
  * **常用微表情预设下拉/多选**：
    * 眼神类：`挑眉`、`瞳孔震颤`、`微眯双眼`、`闭目沉思`、`含泪凝视`、`翻白眼`
    * 嘴部类：`嘴角上扬(冷笑)`、`咬牙切齿`、`倒吸凉气`、`嘴角下沉(委屈)`、`张口结舌`
    * 面肌类：`面部抽搐`、`肌肉紧绷`、`脸颊泛红`、`脸色煞白`
  * **自定义备用**：下拉框最后一项保留“自定义输入”，满足特殊创作。

#### (3) 视线朝向 (`performance.eye_line`)
* **现状问题**：使用自由文本框。
* **改造设计**：
  * 改为 **Segmented Control（分段图标选择器）**：
    * `看向画左 (LOOK_LEFT)`
    * `看向画右 (LOOK_RIGHT)`
    * `直视镜头 (LOOK_CAMERA / 破壁感)`
    * `俯视 (LOOK_DOWN)`
    * `仰视 (LOOK_UP)`
    * `眼神闪躲 (AVERTED)`
    * `闭目 (EYES_CLOSED)`
  * 当用户在 2D/3D 站位板调整了摄影机与角色朝向夹角时，系统**自动联动更新视线方向**。

#### (4) 场景环境 (`environment`) 与 连续性 (`continuity`)
* **现状问题**：每个镜头都留有两个大文本域，需要用户手动重复填写。
* **改造设计**：
  * **场景环境自动继承**：镜头指派了场景（如 `SCENE_LIGHTHOUSE_NIGHT`）后，环境框自动折叠显示：“已继承海边旧灯塔·夜景设定（冷色调、雾气弥漫、应急灯）”，右侧提供“+ 附加天气/光线变化”按钮。
  * **前后镜连续性自动继承**：系统自动比对上一镜头与本镜头的角色、服装、伤势状态。若一致，自动标注“已继承前镜状态（男主身着风衣，左肩受伤）”，避免人工反复录入。

#### (5) 2D/3D 站位板角色与坐标输入 (`StagingBoard.tsx`)
* **现状问题**：`selectedParticipant.label` 允许用户手输角色名，且有 `运动终点 X / Y` 坐标数字框。
* **改造设计**：
  * **角色选择**：改为下拉框，直接列出本场次/本镜头出场的资产角色（如“林默”、“苏清雪”）。
  * **坐标与朝向**：完全通过画布上的角色圆圈拖拽、旋转箭头操作；数字输入框降级为只读或直接隐藏，不再要求创作者手工算坐标百分比。

### 2. 手动生成与控制面板 (`GenerationWorkbench.tsx` / `GenerationControlEditors.tsx` / `MotionControlPanel.tsx`)

#### (1) 时间参数算法级微秒输入 (`time_us`, `start_us`, `end_us`)
* **现状问题**：输入框单位为微秒（`time_us`，如 2,000,000 表示 2 秒），极易因输错 0 导致生成任务由于时间超限而报错失败。
* **改造设计**：
  * 前端界面一律统一为 **秒（单位：s）**，精确到 0.1s（如 `0.5s`、`2.0s`）。
  * 在表演绑定中，直接提供**可视化的时间轴起止滑块**（双滑块区间选择器，0.0s ➔ 3.0s）。
  * 底层向 API 发送 Payload 时由前端自动转换 `time_us = Math.round(seconds * 1_000_000)`。

#### (2) 运动控制技术 ID 与运动笔刷手写 JSON (`MotionControlPanel.tsx`)
* **现状问题**：
  * `maskMediaVersionId` 与 `keyframeMediaVersionId` 为纯文本框，要求用户手打或复制 UUID。
  * `vectorJson` 让创作者手写 `[{"x":0.2,"y":0.3,"pressure":1}]` 坐标数组。
* **改造设计**：
  * **ID 框全面替换为 MediaPicker**：点击弹出项目图片选择器，直接点击缩略图选取。
  * **运动笔刷交互化**：在主画面上覆盖涂抹画布，用户使用画笔在画面上涂抹出运动区域或拉出运动方向箭头，前端 Canvas 自动提取点集并序列化，彻底告别手写 JSON。
  * **主体角色 (`subjectRole`)**：改为下拉单选框（`主角 (subject)`、`面部 (face)`、`肢体 (body)`、`前景 (foreground)`、`背景 (background)` 或当前镜头绑定的角色列表）。

#### (3) Seed 批量实验列表 (`seedBatchText`)
* **现状问题**：单行文本框让用户手输逗号分隔的种子 `42, 43, 44, 45`。
* **改造设计**：
  * 改为 **“起始 Seed + 生成数量（1~8）+ 随机步长”** 控件。
  * 提供“🎲 一键生成 4 个随机种子”按钮，自动生成不重复的随机 Seed 序列。

### 3. 故事工作区与长文导入 (`StoryWorkspacePage.tsx` / `ScriptImportPanel.tsx` / `CreativeLibrary.tsx`)

#### (1) 原文拆解段落范围选择 (`sourceParagraphStart` / `sourceParagraphEnd`)
* **现状问题**：用户看着长文预览，却需要手动在下方输入框填写数字（如起第 1 段，止第 18 段）。
* **改造设计**：
  * 长文预览列表中，每段左侧提供复选框或支持**鼠标划选（Shift + 点击连续选择）**。
  * 后台若解析到了章节标题（如“第一章”、“第二幕”），自动提供**“按章节快速选择”**下拉按钮，点击“第一章”自动高亮选中该章所属的全部段落并自动填充起止段号。

#### (2) 创作资料 Code (`code`) 与 设定 JSON (`initialContent`)
* **现状问题**：
  * 要求创作者手输 `CHAR_HERO` 等技术代码。
  * 初始设定默认为 JSON 文本域。
* **改造设计**：
  * **代码自动生成**：用户输入标题“林默（男主角）”，后台自动生成 `CHAR_LINMO`；用户无需关心代码命名规范。
  * **纯可视化表单优先**：角色设定默认呈现“外貌”、“性格”、“身世背景”、“标志性动作”4 个标准输入项；JSON 模式仅作为折叠的高级模式。

#### (3) 角色提议建档 (`AssetProposalReviewPanel.tsx`)
* **现状问题**：AI 提取出角色建议后，“保留为独立角色”需要手动填写 `CHAR_NAME`。
* **改造设计**：系统已识别出角色名称（如“苏清雪”），自动带入 `CHAR_SUQINGXUE`，提供一键“✅ 保留并建档”按钮。

### 4. 分集策划与分镜批量板 (`StoryboardBatchWorkbench.tsx` / `ShotGroupPlanner.tsx`)

#### (1) 景别类型手输 (`batchShotType` / `shot_type`)
* **现状问题**：批量操作抽屉和分镜编辑框中，`shot_type` 是普通文本框，placeholder 提示 "例如 MEDIUM"。
* **改造设计**：
  * 统一改为**标准景别下拉单选框**：
    * `大全景 (ESTABLISHING)`
    * `全景 (WIDE)`
    * `中景 (MEDIUM)`
    * `中近景 (MEDIUM_CLOSE)`
    * `近景 (CLOSEUP)`
    * `特写 (EXTREME_CLOSEUP)`
    * `主观视角 (POV)`
    * `特异/插镜 (INSERT)`

#### (2) 镜头复制与拆分编号 (`copyCode`, `splitCodes`)
* **现状问题**：复制镜头要求手输 `copyCode`；拆分镜头要求手输 `first_code`、`second_code` 及第一段毫秒数。
* **改造设计**：
  * **自动命名**：
    * 复制镜号：系统自动命名为 `SH_001_COPY` 或自动顺延重排。
    * 拆分镜号：系统自动命名为 `SH_001_A` 与 `SH_001_B`。
  * **时长拆分**：提供**百分比分割滑块**（默认 50%:50%，如 3.0s 拆为 1.5s / 1.5s），创作者拖动滑块即可直观预览两段时长。

#### (3) 节拍编号自增 (`ShotGroupPlanner.tsx`)
* **现状问题**：创建节拍需手动输入 `BEAT-01`。
* **改造设计**：系统根据当前已有节拍数量自动自增带入 `BEAT-02`、`BEAT-03`。

### 5. 声音与 TTS 配音链路 (`DialogueTTSPanel.tsx` / `DialogueGovernanceActions.tsx`)

#### (1) 对白发音映射手输 JSON (`pronunciation`)
* **现状问题**：让用户在单行输入框手输 JSON `{"朝阳":"zhao1 yang2"}`。
* **改造设计**：改为**多行发音校对表格**（左列：多音字/生僻词，右列：拼音与声调下拉选择），系统自动转换并校验 JSON。

#### (2) 对白说话人 (`speaker`)
* **现状问题**：创建和编辑对白文本时，说话人是一个无提示文本框。
* **改造设计**：改为**带搜索建议的下拉选择框（Combobox）**，默认下拉显示本项目已建档的全部角色及“旁白”、“画外音”，避免说话人名称不一致导致角色音色无法自动匹配。

#### (3) 成功 TTS 任务结束登记 (`ttsJobId`)
* **现状问题**：要求用户手输 `ttsJobId`（36 位 UUID）。
* **改造设计**：改为**下拉选择框**，直接拉取当前分集所有状态为 `SUCCEEDED` 的 TTS 任务，展示“台词编号 · 说话人 · 完成时间”。

### 6. 模型、工作流与项目设置 (`ProfileConfigurationPanel.tsx` / `ProjectCreateWizard.tsx`)

#### (1) 契约与工作流 4 个大 JSON 文本域
* **现状问题**：输入契约、参数 Schema、输出契约、资源策略 4 个庞大 JSON 文本域直接暴露。
* **改造设计**：
  * 针对漫剧核心能力（生图 T2I、生视频 I2V、语音合成 TTS）提供**官方预设模板卡片**（如“SDXL Turbo 极速版”、“H3 FL2VA 影视版”）。
  * 用户点击即可自动装配契约，原始 JSON 收折于“开发者高级调试”中。

#### (2) 新建项目规格设定 (`ProjectCreateWizard.tsx`)
* **现状问题**：虽然已有画幅预设，但部分分支仍存在手输宽、高、fps、主语言代码等情况。
* **改造设计**：
  * 画幅比例（9:16 / 16:9 / 1:1）、帧率（24 / 25 / 30 / 60 fps）、语言（简体中文 / 繁体中文 / 英语 / 日语 / 韩语）全部锁定为**标准下拉框或预设卡片**，分辨率由画幅与质量预设自动联动计算锁定。

### 2. 交互封装组件沉淀
1. **`EmotionPicker`（情绪与强度选择器）**：标签点选 + 滑块。
2. **`MicroExpressionSelect`（微表情多选胶囊）**：漫剧高频微表情快捷多选。
3. **`EyeLineControl`（影视视线单选组）**：直观图形化单选。
4. **`TimeRangeSlider`（秒级时间区间选择器）**：将算法 `time_us` 隐藏，前端秒级操作。
5. **`MotionCanvas`（运动轨迹画布涂抹器）**：在画面上直接绘制运动矢量并自动生成坐标。

## 四、 总结与成效预期

通过对上述 6 大模块、共计 28 处不合理输入控件的改造：

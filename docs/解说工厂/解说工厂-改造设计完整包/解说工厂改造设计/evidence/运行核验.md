## 5. 接口核验发现的具体误导

已有分镜引用的角色，资产 API 仍返回 `beat_reference_count=0`。本例 4 个分镜的 `entity_refs_json` 已有真实角色/场景 UUID，但全部实体的这个计数仍为 0。

源码原因：`apps/api/local_drama/api/routes/explainers.py` 的 `_assets_view` 将 `beat_reference_count` 赋为 `len(identity_bindings)`。它统计的是有效身份绑定记录，而非 `explainer_visual_beats.entity_refs_json` 中的出场引用。`apps/web/src/features/explainers/AssetsPage.tsx` 又用它计算“未绑定”并展示“引用 N”。

建议读取模型拆成：

1. `appearance_beat_count`：真正引用该实体的当前有效镜头数，UI 显示“出场 N 镜”。
2. `reference_binding_status`：未设参考图 / 已采用参考图 / 待重做。
3. 身份槽位数量和版本摘要放到展开的技术详情里。

这是实际应用服务写入数据后由真实接口重现的内容语义缺陷；不依赖截图判断。

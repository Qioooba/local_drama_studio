# LocalDramaStudio 产品体验分析报告

> 分析日期：2026-08-24
> 分析范围：功能逻辑、用户操作流程、信息架构、交互设计、后端自动化、布局设计、工作流连贯性

---

## 一、总体印象

LocalDramaStudio 是一个功能完备的本地 AI 漫剧生产系统，具有以下特点：

- **本地优先**：不依赖云服务，所有数据本地存储
- **不可变性设计**：镜头版本、资产版本、生成变体均不可覆盖
- **分集生产模式**：以 Episode 为核心生产单位
- **专业分工**：导演台（镜头选择）、审核（质量把控）、时间线（编排）、交付（导出）
- **Agent 自动化**：整集生产 Agent 可自动推进 8 个创作阶段

**核心问题**：系统在追求架构严谨性的同时，对普通用户的可用性做出了过多让步。许多本应由系统自动处理的事情被推给了用户，造成操作负担。

---

## 二、导航与入口问题

### 问题 2.1 入口层级过深，用户不知道从哪里开始

**现状**：
- 项目列表 → 项目总览 → 选分集 → 分集策划/导演台/审核等，最深需要 **5-6 次点击**
- 侧边栏只有在选中项目后才显示"创作区"和"本集生产"菜单项，初次用户只看到空白的侧边栏提示"选择项目后显示..."
- 没有全局的"下一步"引导

**问题**：
- 新用户或久未访问的用户每次都要从项目列表重新导航
- 不知道当前项目处于生产流程的哪个阶段
- 无法快速到达最近在做的分集

**建议**：
1. 在 AppShell 的顶部栏或品牌旁边增加"最近访问"或"当前生产目标"的快捷入口
2. 项目总览的"按目标开始"卡片应该根据项目当前状态自动高亮最紧急的入口，而不是全部平铺
3. 为每个分集添加"生产状态徽章"（未开始/策划中/生产中/审核中/已完成），在项目总览页显眼展示

---

### 问题 2.2 快捷键系统缺乏可见性

**现状**：
- 导演台的快捷键系统很丰富（J/K 上一镜下一镜、G 打开生成、A 打开资产、F 打开首尾帧等），但在页面上**完全没有可见提示**
- 用户需要阅读源码或通过 Command Palette（`Ctrl+K`）才能发现这些快捷键

**问题**：
- 快捷键是高级功能，但页面没有引导用户发现它们
- 新用户不知道导演台有这么高效的键盘操作方式

**建议**：
1. 在导演台页面底部或 Inspector 面板内增加一个"快捷键"可折叠区域
2. 首次使用时，在关键位置弹出一次性引导提示（如"按 G 可快速打开生成设置"）

---

### 问题 2.3 侧边导航缺少当前页面位置高亮

**现状**：
- AppShell 使用 `NavLink` 配合 `isActive` 来判断高亮，但 URL 参数（`?view=...`、`?step=...`）会导致匹配失败
- 例如：导演台 URL `/projects/xxx/episodes/xxx/direct` 和 `/projects/xxx/episodes/xxx/direct/shot123` 都能匹配到同一个 NavLink，但 Tab 切换时高亮逻辑不够精确

**问题**：
- 用户在导航中看不到自己当前在哪个页面
- 特别是在有 Tab/View 子导航的页面（如导演台的 Inspector 面板切换），容易迷失

**建议**：
1. 改用 `useLocation` 配合 `pathname.startsWith` 做更宽松的高亮匹配
2. 在内容区顶部增加小型面包屑导航（如"项目总览 / 第一季 / E01 / 导演台 / 镜头 5"）

## 三、工作流状态问题

### 问题 3.1 整集生产预检不是自动触发的

**现状**：
```tsx
// EpisodeRunPanel.tsx:115-119
const preflight = useQuery({
  queryKey: ["episode-production-preflight", episodeId, ttsEnabled, productionMode, checkpointPolicy],
  queryFn: () => preflightEpisodeRun(episodeId, ttsEnabled, productionMode, checkpointPolicy),
  enabled: !runId,  // 用户必须进入页面或手动 refetch
});
```

进入整集生产页面时，预检结果需要等首次数据加载完成才显示。阻塞项列出后，用户需要手动点击不同链接去处理（分集策划、资产圣经、诊断）。

**问题**：
- 预检阻塞项分散在不同页面，用户需要反复跳转才能全部解决
- 没有一个统一的"阻塞项仪表盘"聚合所有问题
- 进入页面后，用户不清楚自己的项目在多大程度上准备好了

**建议**：
1. 预检自动执行（不需要 `enabled: !runId` 条件），结果实时更新
2. 在项目总览页增加一个"生产准备度"卡片，一目了然看到全局阻塞项数量
3. 阻塞项应该提供直接的一键处理入口（如"角色张三缺三视图"→ 点击直接打开资产圣经的该角色）

---

### 问题 3.2 失效（Stale）状态缺乏主动通知

**现状**：
- 导演台通过 `useProjectEventInvalidation` 监听 `ARTIFACT_REGISTERED`、`SHOT_REVISION_CREATED` 等事件来刷新数据
- 但 stale 状态只是视觉上的标记（如红色高亮），**没有推送通知**告知用户哪些镜头需要重新检查

**问题**：
- 当用户在导演台工作一段时间后，资产、角色或上游镜头的变化可能影响当前镜头
- 用户不知道哪些镜头的候选已经失效，必须自己主动检查

**建议**：
1. 增加一个"失效通知"徽章，在侧边栏的"审核"入口上显示 stale 数量
2. 当 stale 数量变化时，通过 Toast 消息主动通知用户
3. 在导演台的 ShotNavigator 中，失效镜头应该有特殊标记（如橙色边框）

---

### 问题 3.3 整集生产运行状态不够透明

**现状**：
- 运行中的整集生产依赖 `refetchInterval` 或事件驱动来更新状态
- 阶段进度（`StageCard`）只在用户选择对应阶段 Tab 时才显示详情
- 没有全局的"完成百分比"或"预计剩余时间"在页面顶部醒目展示

**问题**：
- 用户需要主动切换 Tab 才能看到各阶段的进度
- 当前卡在哪一个阶段不够一目了然

**建议**：
1. 在整集生产运行控制区顶部增加一个横向的总体进度条
2. 各阶段用小圆点/方块表示，形成"已完成 → 进行中 → 待处理"的视觉流
3. 当阶段从 RUNNING 变为 BLOCKED 时，主动弹出提示并提供直接处理入口

---

## 四、审核流程问题

### 问题 4.1 三种审核操作概念模糊

**现状**：
审核页面（EpisodeReviewWorkspace）涉及三种不同的操作：
1. **采用候选**（`selectMediaVersion`）—— 从候选中选择一个进入正式流程
2. **批准媒体**（`submitReview`）—— 人工批准该媒体版本
3. **批准整集**（待实现）—— 最终确认整个分集

这三种操作分散在不同的抽屉和面板中，对用户来说**概念不清晰**。

**问题**：
- 用户不知道"采用"和"批准"的区别
- 三种操作的后果和前置条件没有明确说明
- 审核页面的"采用正式版本"入口藏在一个按钮下面，容易被忽略

**建议**：
1. 在审核页面顶部增加一个"审核状态图"或"审核阶段指南"，明确展示：候选 → 采用 → 批准 → 整集确认
2. 为每种操作提供清晰的徽章和说明（如"该镜头已通过人工审核"）
3. 在导演台中完成选择后，直接在同一个界面提供"提交审核"的快捷操作，而不是跳转

---

### 问题 4.2 批量审核功能不够突出

**现状**：
- `ReviewInboxPanel` 提供了批量选择功能，但入口不够明显
- 批量审核需要使用同一个模板，但模板选择界面在一个 Drawer 里

**问题**：
- 用户需要逐个处理候选，效率低下
- 没有"一键全部批准"或"一键全部拒绝"这样的快捷操作

**建议**：
1. 在审核页面的过滤器旁边增加一个"批量操作"按钮组（"批准全部"、"标记待修"）
2. 对于连续的同类型问题（如多个表情不正确的镜头），提供"批量重抽"功能

---

### 问题 4.3 审核→时间线→交付的跳转不连贯

**现状**：
- 审核页面底部有"Render 审核"和"交付交接"两个 Tab
- 点击"交付交接"后只显示一个提示卡片，指向时间线和交付页面
- 用户需要手动导航到时间线，再从时间线导航到交付

**问题**：
- 工作流的线性依赖（审核完成 → 时间线编排 → 冻结 → 交付）没有在 UI 上形成自然的引导
- 用户容易跳过某些步骤

**建议**：
1. 在审核页面提供"完成审核，进入时间线"的显式引导按钮
2. 在交付页面顶部增加工作流进度指示器（当前在哪一步，前置步骤是否完成）

---

## 五、信息架构问题

### 问题 5.1 资产圣经创建后没有明确的下一步

**现状**：
- 资产圣经（AssetBiblePage）是一个复杂的页面，左侧是资产列表，右侧是详情和操作面板
- 创建资产 → 创建状态 → 添加参考图 → 生成多视图/表情/细节，这些步骤分散在不同面板中
- **"下一步"是什么，用户不清楚**

**问题**：
- 角色创建完成后，不知道应该去导演台绑定到镜头
- 三视图生成完成后，不知道应该在分集策划中使用这些角色
- 缺少从资产到生产的使用引导

**建议**：
1. 在资产圣经的 Inspector 面板中，增加"该资产在 X 个镜头中使用"的提示
2. 角色创建完成后，弹出引导提示："是否现在去分集策划中使用这个角色？"
3. 为每个资产添加"生产就绪度"状态（如"缺少三视图"、"缺少表情"），并提供一键生成功能

---

### 问题 5.2 模型配置页面信息过载

**现状**：
ModelsPage 有 5 个 Tab（Profile 契约、Workflow 版本、生成偏好、兼容性存证、本地 LLM），每个 Tab 都有大量的技术细节。

**问题**：
- 用户不知道该在哪里配置日常使用的模型参数
- 高级设置对普通用户来说过于复杂
- "本地与远程 LLM" 配置与"模型与能力"的关系不够清晰

**建议**：
1. 将模型配置分为"基础"和"高级"两个视图，默认显示基础视图
2. 在"生成偏好"Tab 中增加一个"推荐配置"预设，让用户一键应用
3. 增加一个"模型诊断"卡片，一目了然看到当前配置是否完整

---

### 问题 5.3 "故事"与"分集"的关系不够直观

**现状**：
- 故事工作区（StoryWorkspacePage）是项目级的，管理全局故事
- 分集策划（EpisodePlanPage）是分集级的，引用故事中的段落
- 但两者在 UI 上没有直接的视觉关联

**问题**：
- 用户在分集策划中看到镜头绑定的原文引用，不知道怎么回到故事工作区修改原文
- 故事工作区修改原文后，分集的镜头引用如何更新，没有说明

**建议**：
1. 在分集策划的"原文证据"Tab 中，增加"查看原文"的快捷链接
2. 当故事原文修改后，在分集策划页显示"原文已更新，X 个镜头的引用需要重新检查"的提示

---

## 六、交互设计问题

### 问题 6.1 导演台模态框过多，用户容易迷失

**现状**：
DirectorDeskPage 有 6 个可打开的模态框/抽屉：
- SourceDialog（源文本）
- ResampleDialog（重采样）
- CompareDialog（比较）
- ApprovalDialog（批准）
- AdoptionDialog（采用）
- KeyframePickerDialog（关键帧选择）

**问题**：
- 多个模态框同时打开时，Escape 键只能关闭最近的一个
- 用户容易忘记自己打开了哪些模态框
- 模态框之间的操作顺序没有引导

**建议**：
1. 将相关操作合并为 Wizard 流程（如"生成 → 选择 → 批准"三步）
2. 在模态框打开时，顶部显示一个小型进度指示器（如"步骤 2/3：选择候选"）
3. 将关键操作（如"重采样"）改为 Inline 面板而非弹出模态框

---

### 问题 6.2 表单验证反馈不够即时

**现状**：
```tsx
// AssetBiblePage.tsx:132
const createDisabledReason = create.isPending 
  ? "资产正在创建，请稍候" 
  : !newCode.trim() ? "请填写资产代码" 
  : !newName.trim() ? "请填写资产名称" 
  : null;
```

验证信息只在按钮的 `title` 属性中显示，用户需要 hover 才能看到。

**问题**：
- 用户不知道表单哪里有问题，只能逐个尝试
- 错误提示不够显眼

**建议**：
1. 在输入框下方实时显示验证错误（如"请填写资产名称"）
2. 验证通过时显示绿色对勾
3. 提交按钮在禁用状态下也应该显示当前阻塞的原因

---

### 问题 6.3 提交反馈消息不会自动消失

**现状**：
```tsx
// EpisodeRunPanel.tsx:95
const [actionFeedback, setActionFeedback] = useState<string | null>(null);
```

反馈消息（如"已提交暂停请求"）显示后，**不会自动消失**，也不会被明确标记为成功/错误。

**问题**：
- 消息累积，占用页面空间
- 成功的消息和错误消息没有视觉区分

**建议**：
1. 成功消息 3 秒后自动淡出
2. 错误消息保持显示直到用户主动关闭
3. 区分 Toast 通知（轻量级）和内联消息（需要用户注意的结果）

---

### 问题 6.4 加载状态和空状态不统一

**现状**：
- 有的页面用 `loading-state` 类名，有的用 `Skeleton` 组件
- 空状态文案不一致："请先..."、"还没有..."、"当前没有..."
- 加载失败的重试按钮不是每个页面都有

**问题**：
- 用户体验不一致，增加认知负担
- 空状态缺少明确的下一步引导

**建议**：
1. 统一空状态组件，包括：图标 + 标题 + 说明 + 操作按钮
2. 加载失败统一显示"重试"按钮
3. 建立空状态文案规范：格式为"没有 [内容]，请 [操作]"

---

## 七、自动化缺失问题

### 问题 7.1 应该自动执行但需要用户手动触发

| 功能 | 当前行为 | 建议自动化 |
|------|----------|-----------|
| 整集生产预检 | 进入页面后等待首次加载完成 | 进入页面后立即自动执行，且实时更新 |
| 角色三视图生成 | 用户手动从资产圣经发起 | 生成后自动触发"表情生成"任务 |
| 失效检测 | 用户需要主动在审核页查看 | stale 状态变化时主动推送通知 |
| 审核数据 | 用户手动刷新 | 后台每 30 秒自动刷新 |
| 整集生产进度 | 依赖 refetch 或事件驱动 | 增加 WebSocket 或更频繁的轮询 |

---

### 问题 7.2 状态聚合不足

**现状**：
- 项目的整体状态分散在多个页面
- 项目总览页（ProjectHomePage）有"按目标开始"卡片，但不够突出
- 没有一个统一的"生产仪表盘"

**建议**：
1. 在项目总览页增加一个"生产仪表盘"模块，展示：
   - 各分集的生产进度（条形图）
   - 待审核项数量
   - 失效项数量
   - 最近活动时间线
2. 在侧边栏的"本集生产"菜单项上增加未完成项徽章

---

### 问题 7.3 整集生产的阶段切换缺乏引导

**现状**：
- 整集生产有 8 个阶段（ShotPlan → ShotGeneration → ...），但阶段之间的依赖关系没有在 UI 上展示
- 用户不知道当前阶段卡住了应该怎么处理

**建议**：
1. 在阶段标签上增加悬停提示，说明该阶段的作用
2. 当某阶段阻塞时，提供该阶段常见问题的 FAQ 折叠面板
3. 增加"跳过当前阶段"的选项（谨慎使用，需二次确认）

---

## 八、布局设计问题

### 问题 8.1 内容区域没有最大宽度限制

**现状**：
- 大屏幕显示器上，内容区域会撑满整个屏幕宽度
- 特别是表格和列表，在大屏上每行很长但内容很少

**建议**：
1. 设置内容区域的最大宽度（如 1400px），大屏时两侧留白
2. 或者提供"全宽模式"和"舒适模式"的切换

---

### 问题 8.2 资产圣经的左右分栏在小屏幕上表现不佳

**现状**：
```tsx
// AssetBiblePage.tsx:149
<div className="bible-layout">
  <aside className="bible-list" ...>  {/* 左侧列表 */}
  <section className="bible-detail" ...>  {/* 右侧详情 */}
  <aside className="bible-create" ...>  {/* 创建表单 */}
</div>
```

三个面板并排，在小屏幕上需要横向滚动或者挤压内容。

**建议**：
1. 在中等屏幕（< 1200px）下，改为"列表 + 详情"的上下布局，创建表单变为浮动按钮
2. 四个资产分类（角色/场景/道具/服装）的切换应该更醒目，考虑改为 Tab 导航而非按钮

---

### 问题 8.3 交付工作区的四步流程没有视觉进度

**现状**：
DeliveryPage 有 4 个 Tab（预检 → 合成 → 审核 → 打包），但 Tab 本身只是文字标签，没有"已完成/当前/待处理"的视觉区分。

**建议**：
1. Tab 改为横向步骤条，每个步骤显示状态（✓/●/○）
2. 当前步骤之前的步骤应该显示为已完成状态
3. 提供"返回上一步"的导航

---

## 九、工作流连贯性问题

### 问题 9.1 缺少全局工作流视图

**现状**：
用户需要记住整个生产流程：故事工作区 → 分集策划 → 导演台 → 审核 → 声音 → 时间线 → 交付

但整个流程在任何页面都没有全局展示。

**问题**：
- 新用户不知道完整的流程是什么
- 不知道哪些步骤可以并行，哪些必须串行

**建议**：
1. 在项目总览的"本集"区块增加一个"生产流程图"（小型的线性流程）
2. 当前所在的步骤高亮显示
3. 可跳过的步骤用虚线表示

---

### 问题 9.2 音频工作区与视频工作区并行关系不清晰

**现状**：
- 音频工作区（AudioPage）独立于视频工作区
- 但音频（TTS、BGM）与视频最终是要合成的

**问题**：
- 用户不知道应该什么时候开始做音频
- 音频进度和视频进度没有关联展示

**建议**：
1. 在时间线页面增加音频完成度的指示
2. 音频工作区增加提示："建议在视频审核通过后开始制作 TTS"
3. 提供"音频预览"功能，可以不用到时间线就能试听

---

### 问题 9.3 导演台→审核 的来回跳转

**现状**：
用户在导演台工作一段时间后，需要去审核页面批量处理候选，再回到导演台继续。

**问题**：
- 跳转过程中上下文丢失（需要重新加载分集、镜头数据）
- 用户需要记住哪些镜头已经处理过了

**建议**：
1. 在导演台中直接集成"审核状态"面板，实时显示哪些镜头已经审核通过
2. 或者提供"一键切换到审核视角"功能，保留当前导演台上下文
3. 审核完成后，通过 Toast 提示"已批准 X 个候选，返回导演台继续？"

## 十、优先级建议

根据影响范围和实现成本，建议按以下优先级修复：

### P0 - 必须修复（影响核心工作流）

1. **整集生产预检自动执行** — 减少用户手动跳转次数
2. **项目总览增加"生产仪表盘"** — 让用户一眼看到全局状态
3. **审核页增加工作流阶段指南** — 区分采用/批准/确认三种操作

### P1 - 应该修复（影响日常使用体验）

4. **侧边栏增加当前页面高亮** — 改善导航体验
5. **导演台增加快捷键提示** — 提高效率
6. **Stale 状态主动通知** — 避免用户错过重要变更
7. **交付工作区四步流程改为视觉进度条** — 明确依赖关系
8. **反馈消息自动消失** — 减少界面干扰

### P2 - 可以优化（提升产品体验）

9. **资产圣经增加"下一步"引导** — 帮助用户完成生产准备
10. **审核页面增加批量操作** — 提高效率
11. **模型配置页面增加"基础/高级"视图切换**
12. **面包屑导航** — 帮助用户理解当前位置

### P3 - 长期改进（架构层面）

13. **WebSocket 实时推送** — 替代轮询，提升响应速度
14. **全局通知中心** — 统一管理所有提示和通知
15. **移动端适配** — 三栏布局在小屏幕上的表现

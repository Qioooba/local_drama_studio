# LocalDramaStudio 功能与用户体验全面评估报告

- **评估日期**：2026-08-24
- **评估范围**：`apps/web`（React 前端全部页面与关键组件）、`apps/api/local_drama`（FastAPI 后端路由层、任务系统、Episode Run 编排）、既有产品/审计文档交叉验证
- **评估维度**：功能逻辑合理性、用户操作逻辑、使用便利性、阻塞性风险、冗余操作、应自动化而未自动化项、流程连贯性、信息架构与布局
- **方法**：代码逐文件走查（含 文件:行号 证据）+ 设计文档对照（`docs/xinjihua/01、02`）+ 既有审计报告复核（`flash_ui_audit/`、`docs/input-controls-audit-2026-08-24.md`）

---

## 一、总体结论（执行摘要）

产品的**底层任务架构是健壮的**（幂等键、租约协议、durable queue、谱系追踪），但**面向用户的"最后一公里"存在系统性缺陷**。核心矛盾可归纳为五条：

1. **长任务双轨制不彻底**：拆解/生成走了 durable Job + worker（正确），但整集渲染、交付打包、增强后处理、批量 TTS 仍在 HTTP 请求内同步跑 ffmpeg（最长 timeout=900s），且处理函数声明为 `async def` 却调用阻塞代码——**渲染期间整个 API 事件循环冻结，所有页面的状态查询一起失灵**。
2. **"一键整集"前半段是空壳**：Episode Run 的 STORY_PARSE / SCRIPT_BREAKDOWN / ASSET_IDENTITY 等 6 个 stage 只是"校验器"而非"执行器"，生产 run 必然在前半链路 NEEDS_HITL 停机（后端代码自己注释了这一点）。对外能力实际是"从已就绪镜头继续批量生产"，而非"剧本一键成片"。
3. **"下一步"链条断裂**：除交付页内部四步向导外，几乎所有页面完成后没有指向下一阶段的 CTA。理想工作流（故事→资产→策划→导演→审核→声音→时间线→交付）完全依赖用户记忆侧边栏顺序；首页第一卡甚至把用户导到错误页面。
4. **大量本可后台自动完成的事转嫁给了用户**：seed 默认硬编码 42（跨镜头同 seed 风险）、prompt 不从镜头意图预填、缩略图在 GET 时惰性现算（worker 明明支持 MEDIA_THUMBNAIL 却无人入队）、镜头批准后不自动拼装初剪时间线、Worker 未启动只提示"去跑 PowerShell 脚本"。
5. **编辑器数据保护不一致**：导演意图编辑器有完善的 localStorage 草稿 + dirty 守卫（范本），但生成工作台五步向导、分镜编辑计划完全裸奔（内存态，切镜/刷新即清空），时间线草稿用 sessionStorage 关浏览器即丢。

**量化现状**：本报告收录约 90 项发现，其中 P0（阻塞/数据丢失级）18 项，P1（明显影响效率）约 40 项。

## 二、严重度定义

| 级别 | 含义 |
|---|---|
| **P0** | 会直接卡死用户操作、造成数据丢失、或系统性瘫痪（事件循环冻结/队列无人消费） |
| **P1** | 明显增加操作成本、易导致误操作或困惑 |
| **P2** | 体验瑕疵、文案/布局问题 |

## 三、阻塞性问题（最容易卡住用户的点）

### 3.1 后端同步阻塞（P0，最高优先级）

**B-01【P0】整集渲染在 HTTP 请求内同步执行 ffmpeg，并冻结整个 API**
- `apps/api/local_drama/api/routes/timeline.py:282-290` → `application/timeline.py:1153`，经 `_concat_and_mix` 执行多次 `subprocess.run(..., timeout=900)`（`application/timeline.py:1501、1590、1876`）。
- 处理函数声明 `async def` 却直接调用阻塞代码 → 渲染期间**整个事件循环冻结**，包括任务状态轮询、SSE 推送在内的所有 API 一并失灵。一集多镜头+混音时请求可挂 10 分钟以上。
- **讽刺的是异步基础设施已存在**：`POST .../compose:submit`（202+Job，`timeline.py:301-311`、`application/compose.py:56-85`），但直连 render/delivery 同步路径仍保留，两条路径并存易被前端误用。

**B-02【P0】分段渲染同样同步阻塞**：`api/routes/timeline.py:314-321` → `application/timeline.py:1271+`，同一套 concat/mix ffmpeg。

**B-03【P0】交付包构建同步执行转码+烧字幕**：`api/routes/timeline.py:368-373` → `application/timeline.py:1770+`（drawtext 重编码 timeout=900）。

**B-04【P0】增强后处理是多步 ffmpeg 流水线内联执行**：`api/routes/timeline.py:266-271` → `application/timeline.py:1000-1099`：每个 filter 步骤一次 FFV1 中间编码 + 最终 libx264 编码 + 多次全文件 hash/probe，单请求可超 10 分钟。

**B-05【P0】缩略图/filmstrip/波形在 GET 中惰性生成，且每次请求先做全文件 SHA-256**
- `api/routes/media.py:337-361` → `application/media.py:735-818`：每次先 `verify_content_integrity()` 对源视频完整哈希，缓存未命中再跑 ffmpeg。
- UI 打开一个媒体网格 = 几十次"GB 级文件哈希 + 可能的 ffmpeg"，事件循环反复被卡。**Worker 明明实现了 `MEDIA_THUMBNAIL`/`MEDIA_PROXY` 任务类型（`application/worker.py:69-102`），但全仓库没有任何生产代码创建这两类 Job**——能力存在却无人入队。

**B-06【P0】LLM probe 在请求内做真实推理**：`api/routes/llm.py:31-53`，模型冷加载时可阻塞数分钟（chat 超时上限 600s，`infrastructure/local_llm.py:276`）。用户在模型配置页点一次"测试连接"可能让整个应用假死几分钟。

**B-07【P0】Worker 不随 API 启动，队列可能无限期无人消费**
- lifespan 仅做 manifest/LLM/template 同步（`main.py:64-81`）；worker 是独立进程（`scripts/run_worker.py:69-78`），默认 `max_jobs=100` 跑完即退。
- 用户忘记启动 worker 时所有 Job 停留 QUEUED。前端的应对方式只有侧栏一行静态文字"运行 scripts/start.ps1 后自动处理任务"（`AppShell.tsx:153-156`）——**以命令行脚本作为唯一恢复路径，无一键检测/启动**。

**B-08【P0】取消机制形同虚设**：`jobs:cancel` 仅置 CANCEL_REQUESTED（`application/jobs.py:640-653`），但只有 LLM 拆解路径读取该标志（`worker.py:844-848`）。MEDIA_*/COMPOSE/TTS/GPU 任务一旦开始无法中断（`subprocess.run` 无 kill 通道），ComfyGPU 轮询循环完全忽略取消标志（`comfy_jobs.py:156-178`）。**用户点"取消"后 ffmpeg/GPU 仍会跑满全程**。

**B-09【P1】单 worker 串行 + 全局 GPU 门导致队头阻塞**：LocalMediaWorker 一次一个 Job；SQL 层强制全局同一时刻仅一个 GPU Job（`application/jobs.py:371-377`）。一个 15 分钟的整集 compose 会阻塞同 channel 全部 TTS/拆解任务。

**B-10【P1】SSE 实为"60 秒限时轮询"且依赖事件循环存活**：服务端每 0.5s 查库、60s 硬截止（`api/routes/jobs.py:157-173`），无 WebSocket。结合 B-01～B-06：**事件循环一旦被长 ffmpeg 占满，整套"准推送"同时失灵，且多数页面没有轮询兜底**（见 F-16/F-36）。

**B-11【P1】Job 普遍无百分比进度**：GPU/Comfy 任务只回报 QUEUED/RUNNING 相位；CPU 类从 CLAIM 到 COMPLETE 之间只有一次 RUNNING 心跳。唯一有真实 percent 的是 LLM 拆解（`worker.py:828-878`）。用户面对"生成中"可能要盲等几十分钟。

**B-12【P1】claim 入口无条件 reconcile 造成写放大**：`application/jobs.py:347` 空闲轮询每秒一次立即写事务 + 新建连接，busy_timeout 仅 10s，突发写入下可能 `database is locked` 冒泡为 500。

### 3.2 前端交互阻塞（P0/P1）

**F-B01【P0】整集批量 TTS 同步 await、不可离场**：`features/status/DialogueTTSPanel.tsx:66-70`，一次 await 到"整集 TTS 已处理"才返回，期间无进度、离开页面回来无恢复视图。

**F-B02【P0】交付页渲染/打包全程同步 await**：`features/production/DeliveryWorkflowPanel.tsx:48-71,83`——配合后端 B-01/B-03，前端按钮"渲染登记中…"期间页面实质挂起；交付历史还要手点"刷新"。

**F-B03【P1】时间线编排器初始化最多 10 次串行 director-desk 请求，大分集下长时间白屏**：`features/timeline-v2/TimelineComposer.tsx:12-33,278`。

**F-B04【P1】审核页"采用正式版本"抽屉 O(N) 串行批量请求**，候选多时长时间停留在"正在限定本集正式候选…"：`features/episode-review-v2/EpisodeReviewWorkspace.tsx:28-80,115-119`。

## 四、流程连贯性问题（"下一步"链条断裂）

**C-01【P0】首页第一卡把新用户导错页面**
- 项目总览"导入小说 / 剧本"卡片链接到分集策划 `/plan`（`ProjectHomePage.tsx:70`），但导入与 AI 拆解实际位于故事工作区 `/story`（`EpisodePlanPage.tsx:100-102` 自己也承认这一点）。**新用户按首页引导第一步就走错门**。

**C-02【P0】"请先建立季度与分集"是死胡同**
- 项目无分集时提示先创建季度/分集（`ProjectHomePage.tsx:70,80`），但**全前端不存在任何创建 Season/Episode 的 UI**（grep `createSeason|createEpisode` 零命中）——分集只在建项向导里按数量一次性生成（`ProjectCreateWizard.tsx:119-120`），之后永远无法追加。用户被告知去做一件系统里不存在的事。

**C-03【P1】提交成功无下一步 CTA**：GenerationWorkbench 成功后只渲染一行含 Job ID 的 `<code>` 文本（`GenerationWorkbench.tsx:897-902`），无"跟踪任务/前往审核"按钮，该页也不看 Job 进度。

**C-04【P1】Agent Run 结束无收尾引导**：终态只提供"新建生产运行/打开失败 Jobs"（`EpisodeRunPanel.tsx:215`），缺指向 审核→声音→时间线→交付 的引导；BLOCKED 外链跳出后也无回路（`:82`）。

**C-05【P1】侧边栏八个同级平铺入口，零流程进度感**：plan/direct/generation/run/review/audio/timeline/delivery 平铺为同级 NavLink（`AppShell.tsx:133-143`），多少镜已批准、哪一步没做完全无从得知，用户随时漏步骤。

**C-06【P1】TTS 选择候选后缺少"去哪批准"指引**：提示文案无可点击跳转（`DialogueTTSPanel.tsx:15`）。

**C-07【P1】项目卡片 next-action 文案撒谎**：DRAFT/PAUSED/ARCHIVED 分别显示"进入项目/查看暂停原因/查看归档项目"，但全部导航到同一个 projectHome，并无专属视图（`ProjectsPage.tsx:14-19,51`）。

**C-08【P2】导演台"在分集规划中查看原文"深链失效**：链接指向 `/plan#plan-source`，但目标页只解析 `?view=` 参数且不存在该锚元素（`DirectorDeskPage.tsx:464` vs `EpisodePlanPage.tsx:29-41`）。

**C-09【P2】顶栏切换项目丢失分集上下文**：处于分集工作区时切项目直接回 projectHome（`AppShell.tsx:106-109`）。

**C-10【P1】草稿完成后审核面板不自动出现**：拆解 Job 有 3 秒轮询（`ScriptImportPanel.tsx:61-65`），但第 3 阶段的草稿查询无任何失效机制（`AIDraftReviewPanel.tsx:8`），Job SUCCEEDED 后用户必须切走再切回才能看到草稿。

## 五、应该后台自动实现、却要求用户操作的点

**Z-01【P0】"一键整集"前半段六个 stage 是校验器不是执行器**
- `application/episode_front_half_actions.py:1-8` 开篇自述"deliberately does not invent creative facts"；STORY_PARSE 不解析剧本（`:242-272` 只验证已有 commit）、SCRIPT_BREAKDOWN 不发起也不应用 LLM 拆解（`:274-308`）、ASSET_IDENTITY 不处理 proposal（`:328-379`）。
- 结果："极速 Agent 模式"实际从关键帧检查之后才开始自动化，前面必然 NEEDS_HITL 停机。（开发规格 02 增补 E.3 也明文禁止在此之前宣传"剧本一键成片"。）

**Z-02【P0】缩略图/Proxy 不自动派生**：见 B-05。导入/生成成功后应自动入队 MEDIA_THUMBNAIL/MEDIA_PROXY，而不是让用户浏览媒体时触发同步现算。

**Z-03【P0】无自动初剪**：全仓库无 rough cut/auto timeline 逻辑；镜头视频批准后不会自动拼装成集级时间线 revision（`api/routes/timeline.py:116-121` 只接受客户端手工提交 items），用户必须手工构建整条时间线才能进入合成。

**Z-04【P1】Seed 默认硬编码 42，批量默认 43,44,45,46**：`GenerationWorkbench.tsx:200,216,424`。seed_policy 为 EXPLICIT 且不按镜头派生、不检测"连续 N 镜同 seed"。跨镜头忘改 seed 将产出高度相似的废片——这应该是系统按镜头哈希自动派生并在冲突时提醒的事。

**Z-05【P1】Prompt 不从镜头意图预填**：revision 里已有 subject_action/dialogue/camera_plan/creative_intent 结构化事实，Prompt textarea 却始终空白（`GenerationWorkbench.tsx:195,683-689`），也没有"从镜头意图生成"按钮。每镜每 take 都要复制粘贴。

**Z-06【P1】重抽原因每次重复选择，且默认值是个"幽灵选项"**：`rerollReason` 默认 `USER_REROLL` 不在原因网格中（初始无选中态），高频重抽每次都要重选（`DirectorDeskPage.tsx:45-52,118,239`）；seed 有自动 +1 而原因无记忆。

**Z-07【P1】远程 LLM 出境许可每次进页面都要重新勾选**：组件本地 state 未持久化为项目级授权（`ScriptImportPanel.tsx:32,178-181,448-453`）。

**Z-08【P1】模型配置要求用户"手改 URL"选项目**：ModelsPage 空态文案直接写着"在 URL 中指定项目后才会读取该项目范围内的模型许可证存证"（`ModelsPage.tsx:132-136`），页面内没有项目选择器（Jobs/Diagnostics 都有）。普通用户无法自助。

**Z-09【P1】H3 I2V 工作流导入是三段式手工流水线**：创建（暴露 code/prompt/seed/tier/sigma_points/acceleration 底层参数）→ 本地验证 → 发布，三个动作分处不同卡片（`ProfileConfigurationPanel.tsx:583-646,801-831`）。一个 H3 模型可用至少 3 次跨区域点击加参数填写；Profile 契约还是 4 个裸 JSON 文本域（`:82-85`）——这是工程师 schema 编辑器，不是创作者产品。

**Z-10【P1】LLM 配置强制"1.测试 2.同步 3.发布"按钮序列，且任何字段改动即作废全部探测结果**：修正一个拼写错误就要重跑 4 级探测（`LocalLLMConfigurationPanel.tsx:389-413,122-127,327-353`）。

**Z-11【P1】ComfyLab 沙盒要求手改环境变量**："设置 LOCAL_DRAMA_COMFY_DESIGNER_PYTHON 与 …ROOT 后可启动"（`ComfyLabPanel.tsx:44`），无一键修复/检测。

**Z-12【P1】QC 失败自动重抽覆盖面过窄**：bounded reroll 已实现（seed+1、幂等键、上限控制，`episode_worker_actions.py:391-422`），但**只在 Episode Run 内生效**；用户在画布上单独提交的生成 Job QC 失败后没有任何自动处理。

**Z-13【P1】生产档位 tier 是"假旋钮"**：tier 只是冻结元数据，未接入 `resolve_tier`，不影响真实生成参数（G11-completion-report §4.2 自认）。用户切换 FAST/MASTER 档毫无实际效果。

**Z-14【P1】无耗时预估**：设计要求的 p50/p90"预计 2–4 分钟"（02 规格 §76）无任何实现证据；所有长任务都不告诉用户要等多久。

**Z-15【P2】交付历史需手动刷新**；刚创建的 render/delivery ID 只存页面 state 刷新即失（`DeliveryPage.tsx:25-26`）。

**Z-16【P2】角色建议的资产 code 只读不可改、裁决成功无反馈**（`AssetProposalReviewPanel.tsx:26-29`）。

**Z-17【P2】拆解→资产提取半自动**：apply 自动生成 proposals（`breakdown_apply.py:305`）值得肯定，但每条 proposal 必须人工 decide，无自动合并/去重启发式。

## 六、冗余操作

**R-01【P1】多 take 串行提交、中途失败无部分成功报告**：for 循环逐个 plan+submit（`GenerationWorkbench.tsx:440-459`），第 k 个 take 失败时前 k-1 个已入库但界面无从得知，无续传。

**R-02【P1】恢复历史 Variant 存在 N+1 串行请求**（`GenerationWorkbench.tsx:264-286`）；叠加 F-B04、F-B03，"串行小请求瀑布"是全站性能通病。

**R-03【P1】AudioPage 按 tab 绑定查询 enabled + onChanged 手工 refetch 五个查询**而非 key 前缀 invalidate，新增查询容易漏刷（`AudioPage.tsx:33-53`）。

**R-04【P1】双重路由死页面**：`/projects/:id/models|jobs|diagnostics` 在 router 中注册（`router.tsx:62-64`）但全站无任何 Link 指向；侧栏只链接全局版拼 `?project=`。同一页面两套 URL 破坏书签一致性。

**R-05【P2】recover_provider_success 需要人工提供与记录完全一致的 provider_job_id**（`jobs.py:615-638`）——崩溃恢复要求用户翻出系统内部 ID。

**R-06【P2】逐镜批次状态塞 URL**：batch/batchDone 编码进 query（`DirectorDeskPage.tsx:147-179`），几十镜时 URL 极长，且换浏览器即丢。

**R-07【P2】需求编号（FR-/G-/P-/00xx）泄漏为全站可见的小标题**：`DirectorRecipesPage.tsx:6`"0046 · Declarative"、`ComfyLabPanel.tsx:40`"FR-WFL-004"、`JobDetailsPanel.tsx:48`"FR-JOB-005"等，对最终用户全是噪音。

## 七、数据丢失风险

**L-01【P0】生成工作台五步向导全部输入无持久化、切镜即清空**：prompt/控制 JSON/seed 全是内存 state，无 localStorage 草稿、无 beforeunload 守卫；且任一输入变化立即作废 prepared 预检——预检→改一个字→必须从头再预检（`GenerationWorkbench.tsx:195-219,247-256`）。对比范本：导演意图编辑器有完善 localStorage 草稿 + dirty 守卫。

**L-02【P1】分镜编辑计划同样裸奔**：时长/类型/复制/拆分/重排 10+ 个 state 全部在内存，仅 STRUCTURE 抽屉内有 dirtyGuard，抽屉外的表格编辑零保护（`StoryboardBatchWorkbench.tsx:28-56,238`）；其 mutation 错误也不渲染（`:92-104 vs :243-246`），网络失败静默。

**L-03【P1】时间线草稿存 sessionStorage，关浏览器即丢**：文案却说"切换页签或刷新后可恢复"（`TimelineComposer.tsx:88-106,195-203,285`），与导演台的 localStorage 策略不一致。

**L-04【P2】手选镜头被后台刷新重置**：prompts 快照页 selectedShotId 在 shots 数组变化后自动回退第一镜（`EpisodePlanPage.tsx:57-61`）。

**L-05【P2】批次"已处理"标记仅存在于 URL**，非持久事实（`DirectorDeskPage.tsx:147-179`）。

**L-06【P2】「应用到成片」无二次确认**：一键将草稿落地为真实场次/镜头/对白，与全站显式确认哲学不一致（`AIDraftReviewPanel.tsx:35`）。

## 八、功能设计不合理

**D-01【P0】capability resolver 分裂**：新偏好域、旧 Profile/worker、Director 各用不同能力名（`LLM_STORY_PARSE` vs `SCRIPT_BREAKDOWN_LLM` 等），统一前"AUTO 选模型推荐"不可端到端宣传（02 规格增补 B.3，发布阻断 #4，未见修复）。这是"宣传与实现差距"最深的一处。

**D-02【P1】107 个按钮点击无响应**（flash_ui_audit 2026-08-24）：无候选时"采用/用于交付/重抽/对比"等无 disabled 态、无 Toast、无 Tooltip——用户不知道点了没反应是 bug 还是权限。

**D-03【P1】Preflight 有 blocker 仍可继续下一步**：G8 门禁只读展示，"继续到合成候选"无条件可点（`DeliveryPage.tsx:62-64`），门禁形同虚设。

**D-04【P1】任务列表无进度、无筛选、无搜索、失败无入口**：
- 行内只有 type/channel/state/priority 四列（`JobsPanel.tsx:49`），进度藏在 560px 抽屉里；
- 无状态/类型筛选（最多 1000 条平铺肉眼扫）；
- 失败的生成任务渲染纯文本"创作重抽 → Variant Composer"——**全库不存在叫这个名字的页面**，用户被指向无处可去的名词。

**D-05【P1】多季项目无法选到目标集**：应用草稿的目标集下拉只加载第一个季度的分集（`AIDraftReviewPanel.tsx:10-12,35`），第 2 季以后永不可选。

**D-06【P1】自动化任务 max_attempts=1**：任何未归类异常 → FAILED → run PAUSE_HITL（`automation_workflows.py:702,627-629`），磁盘抖动/重启这类瞬时故障也要人工 resume。

**D-07【P1】DAG 推进依赖 worker 进程内回调，崩溃窗口致 run 卡死**：complete 与 step_run 之间崩溃则光标停滞（`worker.py:884-891,743-787`），唯一恢复是手动 POST recover，无看门狗。

**D-08【P1】上游永久失败 → 下游任务永久滞留 QUEUED（孤儿依赖）**：claim SQL 要求依赖全部 SUCCEEDED（`jobs.py:378`），TTS/视频 Job 耗尽重试后 RENDER 任务既不失败也不取消，run 表面 RUNNING 实际死锁。

**D-09【P2】硬编码 fallback Profile UUID + 空 catch 吞错**（`ScriptImportPanel.tsx:186,189-197`）——用未知版本的模型提交拆解，用户毫不知情。

**D-10【P2】资产圣经入口的 episode 参数被静默丢弃**：ProjectHome 带 `?episode=` 打开，AssetBiblePage 根本不读（`ProjectHomePage.tsx:72` vs `AssetBiblePage.tsx:59-62`）。

**D-11【P2】MediaLab 是机器级沙盒却锁死在项目命名空间**：Comfy 工作流调试本质与项目无关（页面自述"实验结果不会自动进入正式资产"），逻辑上应属系统工具区顶层（`router.tsx:65`、`MediaLabPage.tsx:11`）。

**D-12【P2】Canvas 叙事分裂**：侧栏叫"高级画布"归工具区，ProjectHome 又包装成四大目标之一的"自由创作"，新用户不确定它是否必经环节。

**D-13【P2】DiagnosticsPage 在 try/catch 中条件调用 Hooks**（`DiagnosticsPage.tsx:34-42`）——hook 抛错会引发整页崩溃而非降级。

## 九、导航与信息架构

**N-01【P1】全应用不存在首次使用引导（onboarding）**：模型未配置、Worker 未启动、项目未创建之间没有任务式串联指引；唯一的上下文提示是侧栏两行静态文字（`AppShell.tsx:132,143`）。新用户的真实首屏很可能是"本地 Worker 未运行：运行 scripts/start.ps1"。

**N-02【P1】分组语义自相矛盾**：同一"项目维护"页在命令面板属"系统"（`AppShell.tsx:19`）、在侧栏属"工具区"（`:131`）；QC 策略/导演配方/生产设置等治理配置插在 故事/资产圣经 之后、工具区之前，打断创作动线（`:125-127`）。

**N-03【P2】系统区默认折叠**：任务/模型/诊断三大监控入口藏在 `<details>` 后，仅当已在这些页面才展开（`AppShell.tsx:144`）；且"创作区"标题下第一项却是全局"全部项目"（`:119-120`），名不符实。

**N-04【P2】页头徽章用架构宣言当口号**："SQLite durable queue · LOCAL_ONLY"、"SSE / 发件箱"、"显式版本 · 禁止静默回退"（`JobsPage.tsx:50`、`JobsPanel.tsx:49`、`ModelsPage.tsx:70`）——这些是写给开发者看的设计文档语言。

**N-05【P2】每页头部固定"大段说明文字+宣言徽章"模式**，首屏信息密度过高、行动入口被推低（`ModelsPage.tsx:72-74`、`ProductionSettingsPage.tsx:76-78` 等）。

## 十一、可靠性隐患（后台问题，但直接影响体验）

1. **租约过期恢复全靠人工精确输入**（D-05/R-05）；进程在 `queue_prompt` 成功后、`attach_provider` 前崩溃会导致 Comfy 白跑 GPU 而本地重复出图（`comfy_jobs.py:112-129`）。
2. **outbox webhook 投递是被动拉取**，需客户端自行调 `POST /events:deliver`，无定时派发器与 TTL 清理（`api/routes/jobs.py:176-181`）。
3. **Job 无暂停语义**：Episode Run 的 pause 只阻止下一个 step，正在跑的和已入队的照常执行（`automation_workflows.py:780-806`）。
4. **帧锚提取需逐帧 ffprobe 解码**（timeout=120s，`application/timeline.py:571-665`），长视频下请求秒级到分钟级。
5. **上传端点把最大 100MB 视频整体读入内存**（`api/routes/media.py:76-139`）。

### 第二批（打通流程连贯性）

# 0. 这次改造如何成功

这不是一个“开几个新页面”的需求，而是一次**在不破坏底层生产证据链的前提下，重构创作者主工作流**。

因此，项目成功标准不是：

> 新导演台看起来漂亮。

而是同时满足：

1. 创作者从剧本到成片路径明显更短、更清楚。
2. 单个坏镜头可以局部修复，不需要重跑整集。
3. 角色/场景资产可以长期复用和锁定。
4. 首尾帧、候选、重抽、模型 override 在同一镜头上下文里完成。
5. 一键整集生产可以暂停、恢复、追溯和局部续跑。
6. 旧项目、旧数据、旧审计、旧候选、旧时间线不能丢。
7. 基础开发 Agent 按本文步骤做，不需要自行猜架构。
8. 测试先于发布门禁，不能以“页面能点”为完成。

## 1.2 本次审查环境的实测状态

本次静态/局部动态审查中：

### Maintainability audit

运行：

```text
python scripts/maintainability_audit.py
```

结果：

```text
status = PARTIAL
deterministic_contracts_passed = true
hard_failures = []
domain_boundary_passed = true
concrete_infrastructure_boundary_passed = false
```

具体问题是 application / 少量 route 对 SQLite、Comfy、manifest 等 concrete infrastructure 的直接依赖。

### API suite

尝试全跑 API tests 时，审查容器并非项目声明的 Python 3.12 环境，而是 Python 3.13；项目 `pyproject.toml` 明确要求：

```text
>=3.12,<3.13
```

首次可定位失败为：

```text
apps/api/tests/test_audio_qc.py::test_audio_qc_records_real_lufs_true_peak_peak_and_clipping
```

失败原因为审查环境中：

```text
本机 FFmpeg 不可用
```

完整 suite 没有在该非标准环境中跑完，因此**不能写成“API 测试通过”或“API 测试失败”**。

正确表述：

> 当前代码有成熟测试库存；本次外部审查环境不满足项目 Python/FFmpeg 本地运行前提，完整 gate 尚未在标准 Windows x64 项目环境复验。

### Web

审查工作区没有安装 `apps/web/node_modules`，因此未在本次容器里运行：

```text
pnpm --dir apps/web build
pnpm --dir apps/web test
```

这同样不构成源代码失败证据。

# 3. PR 大小规则

基础 Agent 最容易犯的错误是：

> “顺便重构了 37 个文件”。

必须限制。

## 3.1 普通 PR

建议：

```text
< 800 effective LOC change
< 20 files
```

不是硬性机器规则，但超出必须解释。

## 3.2 Migration PR

一个 migration + repository + test 可以单独 PR。

不要把：

```text
0042 + 0043 + Director UI + model picker
```

塞一起。

## 3.3 UI Skeleton PR

可以先：

- route；
- layout；
- mock DTO；
- component tests；

不接真实生成。

下一 PR 接 backend。

这样更容易做视觉和数据层独立 review。

# 48. Rollback 策略

## 48.1 UI rollback

Feature flag 回旧 UI。

## 48.2 Backend code rollback

新 schema 是 additive，旧 backend 尽量仍能运行。

但如果旧 backend 对未知 schema 无问题，可以 code rollback。

## 48.3 DB rollback

优先：

```text
restore pre-migration backup
```

而不是依赖复杂 downgrade。

如果 migration 后产生重要新数据，不能简单 restore 丢数据，必须编写 export/repair strategy。

因此 release 初期要缩短观察窗口，不要一升级就连续创作大量新项目再考虑回滚。

# 124. 最终验收口径

这个重构真正完成时，用户的心智应该从：

> “这个软件有很多 Panel，我得记住资产在哪、生成在哪、审核在哪、首尾帧在哪、Profile 在哪。”

变成：

> “我先把剧本和资产准备好，然后按集做；当前坏哪一镜，我就在导演台修哪一镜；要自动就让 Agent 跑整集，要精修就打开镜头；模型、参考图、首尾帧、候选和声音都围绕当前镜头工作。”

而开发者的心智应该从：

> “有需求就再加 route、table、panel。”

变成：

> “先确认事实属于哪个 bounded context，复用哪个既有真值，通过 Port/Command/Query 加能力，再把它投影到导演台。”

只有这两个心智同时改变，LocalDramaStudio 才算真正从“功能集合”升级为可长期迭代的 AI 漫剧生产系统。

## H. 性能与规模验收

最低 fixture：

- 20 万中文字、5000 passages。
- 100 集、每集 100 镜；单集压力 1000 镜。
- 500 资产、每角色多状态/多参考。
- 10,000 Job/Attempt/Audit rows。
- 100GB 媒体目录，含代理、缩略图和孤儿 staging fixture。

预算在目标机器复测后锁定，首轮建议：

- Projects/Home warm navigation p95 < 300ms（缓存后）。
- Director aggregate 本地 DB p95 < 500ms，切镜已缓存 p95 < 150ms；不随 Take 全量线性膨胀。
- 1000 镜 rail 首次可交互 < 2s，DOM 行数由虚拟化限制。
- 搜索/筛选响应 < 100ms；输入不中断。
- long doc/mass media hash 使用 streaming，进程额外内存有固定预算。
- DAG 构图/投影 10k nodes 不阻塞 API event loop；批量操作分页/分块。

性能 evidence 记录 CPU/GPU/RAM/磁盘、fixture hash、冷/热缓存和样本数；只报一次最快值无效。

## I. 安全与隐私验收

LOCAL_ONLY：loopback bind、路径约束、symlink/traversal、导入炸弹、恶意文件名、FFmpeg 参数注入、日志脱敏、包导出 secret scan。

Connected Edition（若批准）：

- vault reference 不泄漏；日志/SQLite/export/localStorage/URL 无 Key。
- 每次外发显示 provider、素材类型、地区、估算费用与 consent。
- 项目/资产 `no-egress` 策略优先；离线默认拒绝，不静默上传。
- rate limit/429、账单上限、取消、超时、重放/幂等、供应商内容政策。
- Provider 响应只保留必要证据；原始敏感 body 有生命周期。

安全失败为 release blocker，不以“本地个人工具”豁免。

## J. 发布、灰度与回滚

### J.1 Feature flags

保留现有 V2 flags；页面内部大改增加短生命周期 flags，例如 `DIRECTOR_FOCUS_LAYOUT`、`TASK_WORKSPACES_V3`、`CANONICAL_CAPABILITY_RESOLVER`、`PRODUCTION_DAG_FRONT_HALF`。每个 flag 必须有 owner、默认值、退出日期和删除 PR；不能永远双写。

### J.2 灰度顺序

1. 开发 fixture + read-only smoke。
2. 复制的旧项目；不在唯一生产项目首测迁移。
3. 内部项目，启用 read path；compare old/new projection。
4. 单集真实生成，设置费用/资源上限。
5. 全剧运行与恢复演练。
6. 签收、更新 release evidence、再移除旧 UI owner。

### J.3 回滚原则

- UI route/flag 可切回旧 owner，但不能复活旧 App shell。
- 数据迁移优先 forward-compatible；新表/列保留，旧代码忽略。
- 新 resolver 双读阶段保存 compare report；发现不一致停止执行，不静默切回。
- DAG/worker 停止接新任务，不删除进行中 Job；恢复后 reconcile。
- Storage operations 回滚先停止 ingest，跑 reconciler/备份，不能直接删 staging。

## K. Go / No-Go

任一项成立即 No-Go：

- Episode Plan 仍可进入默认错误页。
- Director 在任一要求宽度横向溢出或 Inspector 不可达。
- 非首镜可被静默替换为第一镜。
- capability 在 UI 与 worker 解析不同，或首尾帧被静默降级。
- API/Web gate 红且无批准的、时限明确的例外。
- P12 用伪造证据变 READY，或旧 App 被恢复。
- migration 未在复制 DB 做升级/恢复。
- worker 状态文案与真实 supervisor 不一致。
- selected/adopted/approved 被合并，或机器 QC 自动批准。
- 云 Key/外发没有 vault/consent/审计。
- 新 UI 丢失旧项目数据、历史候选、冻结时间线或 Job 恢复能力。

Go 必须附机器可读 evidence、三类 fixture 路由报告、关键断点截图、迁移/恢复报告、性能与安全摘要、产品/UAT 签收。文档或截图“看起来完成”不构成发布证据。

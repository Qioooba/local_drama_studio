## 0. 核心结论（先给结论）

1. 五份报告对根因的判断一致：产品拥有严格的本地生产与版本基座，但把过多工程契约、状态机和机器标识暴露给创作者。优化目标不是“减少所有确认”，而是把确定性计算、查询和派生下沉，同时保留会改变正式血缘、审批事实或交付事实的显式人类决定。
2. 当前工作树已吸收一部分输入选择器、结构化编辑器、媒体选择器和自动代码能力，但**不能使用“约 80% 已完成”这一未经验证的比例**。本次复核已发现多处“界面存在但逻辑未闭环”以及方案状态与代码不符的问题。
3. 后端同步长任务、媒体惰性派生、任务取消、DAG 恢复、能力命名和 tier 真值均直接影响用户体验，属于本长目标实施范围，不能仅以“架构延期”结案。它们会按风险拆成独立工作包并逐项实现、测试；只有确因领域约束不合理的建议才会明确跳过。
4. 优先级按“系统阻塞/数据丢失 > 流程死路 > 错误输入 > 状态迷失 > 视觉效率”排序；同一批次先修行为与事实，再做视觉重排，避免漂亮界面掩盖错误状态。

## 0B. 不可破坏的产品与领域约束

1. **本地优先真实边界**：保持 `LOCAL_ONLY`，不引入云计费、多租户或静默远程调用；远程 LLM 必须显式授权并可追踪。
2. **正式事实不可覆盖**：镜头 revision、媒体版本、时间线 revision、审批与交付记录继续追加式写入；UX 简化不能变成覆盖历史。
3. **选择不等于批准**：候选采用、机器质检、人工批准、整集确认是不同事实。可以在一个连续向导里解释和串联，但不能在后台悄悄合并。
4. **确定性工作自动化**：编号、seed 派生、能力裁决、媒体查询、状态聚合、派生缩略图、可恢复重试等不需要创作者重复确认。
5. **破坏性/正式化动作显式确认**：应用 AI 草稿到生产实体、撤回授权、冻结/交付、批量拒绝等保留语义清楚的确认和影响摘要。
6. **状态必须说真话**：未实现的前半段自动化不得称“一键成片”；未接入真实参数的 tier 不得作为有效旋钮；按钮禁用必须同时给出原因与恢复入口。
7. **长任务不占用请求**：预计超过 1 秒、依赖 ffmpeg/模型/GPU 或可被取消的任务统一走 durable Job，HTTP 返回 202 与可恢复 Job ID。
8. **桌面生产优先**：1440/1280/1024 三档无横向页面滚动；移动端只保证监看，不承诺复杂编辑。

## 0D. 明确调整或不采纳的建议

| 来源建议 | 决策 | 理由与替代方案 |
|---|---|---|
| “一键全部批准/拒绝” | 调整 | 批量批准必须先通过同模板预检与必填人工检查；批量拒绝保留原因，但提供模板。避免把人类审核伪造成系统自动事实。 |
| “审核和采用合并为一步” | 不采纳 | 选择正式候选与人工批准是不同血缘事实。用连续向导和下一步 CTA 降低认知，不合并领域动作。 |
| “时间线 stale 自动更新并冻结” | 调整 | 自动同步只能创建/更新草稿并重新预检；冻结仍需显式确认，因为它决定交付权威版本。交付页可提供一个组合确认流程。 |
| “Frame Bridge 默认自动锁定” | 调整 | 同场连续镜给出可撤销建议；只有规则无歧义且展示来源时才可默认采用。跨场/跳切/角色状态冲突不静默锁定。 |
| “生成三视图后自动触发表情包” | 调整 | 可配置自动化策略，默认展示建议并批量确认；GPU 成本与模型能力未确认时不自动消耗资源。 |
| “移动端完整适配” | 跳过 | 现有设计系统明确桌面生产优先。移动端只做监看、状态和安全操作，复杂导演/时间线编辑不在产品目标内。 |
| “所有内容区域统一 1400px 最大宽度” | 调整 | 表单/文档页限制阅读宽度；导演台、时间线、媒体对比保持工作台全宽。全局硬限制会损害专业编辑效率。 |
| “去掉分镜两阶段提交” | 不采纳 | 结构重排会写入不可变生产事实，必须保留计划/预检/提交；改为全屏可视化预览与更清楚的影响摘要。 |
| “WebSocket 替代所有轮询” | 调整 | 先修事件循环阻塞并为关键视图加入轮询兜底；SSE/轮询足以满足本地单机场景。只有数据证明延迟或连接成本不足时再引入 WebSocket。 |

### 2.1 导演台 · 运镜能力自动裁决 + 保存并就绪（`features/director-v2/DirectorIntentEditor.tsx`）

**目标**：消除“改完字段必须多点一次裁决按钮”和“先保存再标记 Ready 两步等待”。

- **自动裁决**：用 `useEffect` 监听 `shot_type / movement / direction / intensity / curve / profile_version_id / prompt_text` 变化，`setTimeout` 防抖（沿用现有 `DRAFT_DEBOUNCE_MS`），自动调用 `resolveProfileCameraPlan` 并把 `mode`/`camera_plan` 写回草稿。保留“按 Profile 裁决”按钮作为“强制刷新/出错重试”兜底。
- **保存并就绪（Save & Ready）**：脏草稿通过 `saveShotRevisionAndMarkReady` 在单一数据库事务中同时创建 revision、设置 READY、写审计/outbox；stale 冲突零写入并保留前端草稿。净表单沿用单独 READY 命令；`Ctrl+S` 仍只保存。
- 校验逻辑 `localMissing` 去掉“按 Profile 裁决运镜能力”这一手工门槛（现不再需要用户手动裁决）。
- 保持既有 `dirty` 守卫、`beforeunload`、快捷键、草稿缓冲与测试兼容（`DirectorIntentEditor.drafts.test.tsx` 依赖的 `主体动作` 标签等未变）。

### 2.1A 导演台 · 剧本/连续性/站位建议的来源与 stale 闭环（`application/director_desk.py` / `DirectorIntentEditor.tsx` / `StagingBoard.tsx`）

- 剧本推导只读取已经由人类应用为正式场次的拆解事实，并通过 `script_breakdown_scene_applications` 冻结的草稿修订、场次号和场内镜头顺序定位当前镜头；未应用草稿不进入导演台。建议提供动作、画面意图与对白，显示源文档/场/镜并以内容 SHA-256 作为来源指纹。
- “采用到本镜”才写入 Director 草稿，同时在 `suggestion_sources.script` 保存来源指纹、修订 ID 和可读标签。场景环境与同场上一镜连续性采用时分别保存 scene revision 和上一镜 shot revision ID；来源变化后 read model 返回 `stale_reason`，界面以文字+暖色边框提示“重新采用并复核”，不依赖颜色传意。

- 所有建议都是 opt-in；它们不会在加载、拖动或来源更新时静默覆盖已写的情绪、视线、动作或连续性。保存仍走既有不可变 Director revision、脏表单保护与乐观并发门禁。

### 2.19 AI 草稿 · 不覆盖模型原稿的人工派生修订（`0056_breakdown_draft_revisions.py` / `breakdown_revisions.py` / `AIDraftReviewPanel.tsx`）

### 2.20 生成 · Multi-Take 局部失败续传与镜头级草稿隔离（`GenerationWorkbench.tsx`）

- 浏览器草稿 key 改为 `project + shot` 作用域；切换镜头只恢复该镜草稿，旧全局 key 只迁移一次。自动派生 seed 属于默认值，不再单独把页面标成“有未保存修改”。

- 草稿按 episode 持久化，并冻结涉及镜头的 revision；任一源镜已变化就拒绝恢复并删除 stale 草稿，避免旧布局覆盖新事实。单镜编辑与结构编辑都具备 dirty、beforeunload、放弃和异常反馈。

### 2.23 声音、字幕与时间线 · 权威安全派生和 DRAFT 自动初剪（`timeline.py` / `SubtitleRevisionPanel.tsx` / `TimelineComposer.tsx`）

- 新增只读 `GET /episodes/{episode_id}/subtitle-draft-plan`。它按镜头顺序读取每条对白最新文本 revision 与最新 TTS selection；selection 必须仍指向最新文本且媒体完整性为 VERIFIED。返回中冻结 text revision/hash、selection、candidate、媒体 version/hash/时长和 timing basis，并逐条报告未采用、旧文本或未验证媒体。
- 自动草稿的文字始终来自对白 revision，并再次在选定的已解析源剧本中按顺序定位；TTS 只贡献时长。如果 TTS 太短导致超过 25 CPS，计划只延长 cue 时长，不改文字。多源权威、原文不匹配或没有当前采用结果会形成 blocker；接口明确 `would_create_revision=false / mutated=false`。
- 字幕页通过手动按钮或声音页深链加载这份计划。已有人工字幕时第一次点击只提示，第二次才确认覆盖；完整/部分草稿都会展示缺失明细，正式 revision 仍需用户校对并通过原有 SCRIPT authority、无重叠和 CPS 服务端校验。

### 2.24 ComfyLab · 有界自动检测与安全持久化配置

- `POST /comfy-lab:discover` 只检查当前配置、环境变量、工作区/父目录及 C/D/E/F 盘固定 `ComfyUI` 根目录，并在每个根目录检查 portable Python、`.venv`、`venv` 与当前 Python；扫描集合有确定上限，不做磁盘递归。
- “自动检测并配置”是明确用户动作。它不启动 ComfyUI、不发网络请求；候选必须是普通文件/目录且不能是符号链接，端口必须在 1024—65535，随后才原子写入工作区 `work/comfy-lab/launch-config.json`。
- 配置事实区分环境变量、已保存和未配置来源；未找到时列出实际检查路径，用户能判断应把 ComfyUI 放在哪里，而不是得到泛化“配置环境变量”错误。

### 2.25 GPU Provider · 无需精确 Attempt ID 的成功恢复

- Provider 已成功时复用原有恢复命令，复制输出、幂等登记 artifact，并同步收敛 Attempt 与 Job；Provider 不可达时返回 deferred 而不是让 Worker 崩溃。手工恢复入口仍可用于诊断，但不再是日常恢复前提。

## 5. 设计取舍说明（为什么某些“文档建议”未照做）

1. **采用页面内全宽编排，但保留两阶段提交（分镜批量板）**：旧窄 Drawer 已取消，拖拽、比例拆分和撤销栈都在原分镜上下文内完成；“先本地草稿→服务端预检→明确提交”的不可变语义保留。布局效率与数据安全不再被当成二选一。
2. **保留单个镜头“编辑详情/渲染”两次意图确认**：因为“选择候选”与“批准”是严格分离的幂等动作（产品核心约束），文档说的“合并为一步”会破坏血缘语义；本批以“保存并就绪”“一键交付”这类强引导来降低重复，而不是合并语义。
3. **`ReviewInboxPanel` 批量拒绝仍要求原因**：批量操作可能影响多镜，强制原因符合高质量工作流；本批提供“模板短语”降低负担而非去掉原因。
4. **预检门禁（D-03）**：本批对交付页做了“阻塞时禁用”，但坚持保留“不可变可读”的预检展示，把决策权交给用户的同时给出明确就绪状态。

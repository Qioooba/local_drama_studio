# 创作者主链路审计与重构报告

> 日期：2026-08-24  
> 范围：项目创建、故事到角色建档、资产创建、发布规格、品牌水印、本机模型与相关阻塞  
> 方法：代码与路由审计、交互状态审计、桌面/窄屏真实浏览器验收、单元与生产构建回归

## 结论

项目已经具备持久任务、不可变版本、媒体选择器、结构化生成参数、项目/季度/分集上下文等扎实能力；当前最影响创作者的根因不是缺功能，而是**创作入口仍按工程配置顺序组织**：先暴露 code、路径、Profile、Plan、预检和 Worker，再让用户写故事。

本轮没有在旧六步流程上继续加提示或兼容分支，而是重做了完整入口：

`创建作品 → 导入原稿 → 审核拆解 → 角色建档 → 资产圣经 → 第一镜`

系统负责能确定的内容，创作者只负责作品决策和不可替代的人审。

## 已完成的结构性改造

### 1. 项目创建从六步配置台重做为三步创作向导

新流程只有：

1. 作品信息：标题、季度数、计划集数、目标时长。
2. 创作方式：发布画幅预设、语言、字幕方式，以及“先开始创作 / 同时配置现有模型”。
3. 确认创建：后台自动预检，用户最后显式创建。

后台自动处理：

- 项目技术标识；
- 画幅对应的宽、高、fps；
- 字幕语言；
- Production Plan code/title；
- Delivery Target code/title/path；
- 已发布能力的推荐绑定；
- 目录、空间和配置预检。

默认推荐“先开始创作”，模型列表即使仍在加载也不再阻塞故事工作区创建。技术标识仅在冲突或兼容既有目录时通过高级折叠覆盖。

### 2. 故事工作区按真实创作顺序重做

- `/story` 默认落在“导入原稿”，而不是故事圣经。
- 阶段顺序调整为：导入原稿 → 审核拆解 → 角色建档；故事圣经标记为随时维护资料。
- 删除重复顶部导航，只保留一套 EntityRail。
- 删除没有当前任务的常驻 Inspector，把宽度还给正文和拆解内容。
- 桌面为导航 + 内容，窄屏把导航收为“选择阶段”抽屉。
- AI 拆解完成后自动进入审核，不要求用户回忆阶段编号。
- 去除 creator 主路径中的 `FR-ING-001`、`commit`、`WorkerSession`、`第 3 阶段` 等实现语言。

### 3. 项目首页改为“从故事到第一镜”

下一步排序改为：

`项目结构 → 故事原稿 → 角色资产 → 制作方案 → 模型能力 → 导演意图 → 生成`

只有当用户确实走到模型绑定或生成阶段时，才显示 Worker 恢复提示；故事创作期不再被生产环境警告打断。

### 4. 消除端口漂移造成的假死

本机应用的安全边界仍保留实例令牌和恶意来源拒绝，但写请求来源判断从“固定列出 5173”改为：

- 显式配置的来源继续允许；
- HTTP `localhost` 或字面 loopback IP 的任意合法端口允许；
- LAN、伪装域名、HTTPS lookalike 和公网来源继续拒绝。

这样 Vite 自动选择 5174/5175 时不会把本地界面变成只读，同时没有扩大到局域网或公网。

### 5. 发布设置从工程配置台重做为平台选择

- 主路径只问“作品准备发布到哪里”，平台使用下拉选择并展示人可理解的画幅与时长。
- 平台 preset 创建后由后端在同一事务中自动成为项目唯一当前版本，不再要求第二次“选择并启用”。
- 新建目标、新建目标版本和历史版本切换共享同一条项目级激活不变量，始终只保留一个 ACTIVE 版本。
- code、相对目录、宽高、fps、码率都由 preset 或语义控件推导；非平台规格收进高级折叠。
- Profile、版本号、历史任务影响从首屏移入“高级：查看生效版本与历史任务影响”。

### 6. 角色造型、资产与本机模型改为语义输入

- “身份包”主文案改成“角色造型参考”，新建时只填造型名称，系统生成 `LOOK_*` 标识。
- 资产与剧情状态创建不再显示 code 输入；类型使用中文下拉，资产/状态标识在提交时生成。
- 资产列表和准备路径不再用机器 code 充当主要信息。
- 本机模型主路径改成“用途 + 从电脑选择文件”，模型类型、验证能力和 code 自动派生。
- 局域网工作站扫描并入同一个模型添加流程，删除页面上重复的第二套扫描入口。

### 7. 品牌、水印与合规从三套技术表单合并为一次保存

- 删除 BrandKit code、JSON token 和毫秒输入。
- 用户只选择规范名称、主色、水印文字/位置、最长分钟数。
- 一次“保存发布规则”后台顺序创建视觉规范、水印规则和发布检查版本。
- 机器标识与已生效版本仅在折叠详情中展示；人工/平台合规确认仍保持人工责任。

## 输入控件原则与当前判定

### 应自动生成

- project/asset/identity/workflow 等机器 code；
- 输出目录和交付路径；
- 宽高、fps、字幕语言等可由语义预设推导的字段；
- 可查询的 Profile、Job、MediaVersion 默认选择与推荐。

### 应使用下拉、单选或选择器

- 画幅、语言、字幕、生产质量、情绪、镜头类型、构图、运镜方向；
- 项目内媒体、文档、授权证据、成功任务；
- 平台交付规格和本机已发现模型。

### 应保留文本输入

- 标题、故事、对白、动作、创作意图、连续性说明；
- 审核结论、拒绝/撤回理由；
- 专家模式中的提示词模板与必要的兼容覆盖。

### 不应后台静默执行

以下动作刻意保留人类决定：选择原文范围、开始会消耗模型资源的 AI 拆解、应用 AI 草稿、批准/拒绝媒体、冻结版本、撤回授权、正式交付。自动化负责准备、推荐、预检和恢复，不替创作者作不可逆判断。

## 第二阶段：导演到交付主链路已完成

### 8. 模型页分成创作者能力与专家契约

- 默认任务改为“项目生成能力”，创作者按用途、项目、集和镜头选择，不先编辑 Profile/Workflow 合同。
- 能力、项目、季、集下拉只显示人可理解标题；技术码和工程契约进入专家区。
- 自动推荐/固定版本改为单选，能力版本显示明确的人类版次，重复标题不再无法区分。
- 删除强制“变更原因”文本框：保存范围、能力和选择方式由系统自动生成审计说明，特殊备注仅在专家区可选填写。

### 9. 自动化重做为一次准备、一次确认、后台连续执行

- 创作者只选“整剧一键编排”和可选任务名；系统自动创建工作流、生成机器 code、检查任务上限并冻结计划。
- 活动执行自动恢复，后台 Worker 连续推进，不再要求用户点击“执行一步”。
- 只有资源消耗启动和真实人工门禁保留确认；诊断流、手动计划、脚本接口和回调按需挂载在专家区。

### 10. 镜头生成合并重复预检并后台化复现参数

- 主流程改为：方式与镜头 → 输入与控制 → 检查并启动 → 创作分支 → 人工审核。
- 生成能力自动推荐，候选数量改为有限下拉，Seed、能力 code、计划 hash 等复现信息移入专家区。
- “先预检、再点启动”合并为“检查并准备生成”，后台完成计划后只弹一次资源确认。
- 图片生成视频明确要求已批准首帧；产生候选与采用/批准继续分离。

### 11. 导演、审核与逐帧批注改为创作者语言

- 导演重抽不再要求用户输入 Seed，系统生成不碰撞复现参数并保留分支。
- 审核列表、批量选择、机器检查、正式采用和状态全部翻译；UUID、hash、内部阶段、模板码与 revision 进入专家详情。
- 逐帧批注子功能已重做：不再手输毫秒或选择带 ID 的返工 Job，保存时自动读取播放器当前时间，用户只选中文问题类别并描述问题。
- 单项目/单分集时自动隐藏无意义筛选，减少重复控件。

### 12. 交付把安全自检真正放到后台

- 交付页使用“交付检查 / 合成候选 / 审核成片 / 打包交付”，旧时间线刷新只保留一次不可变新版本确认。
- 页面不再暴露 manifest、shot_id、revision、PASS/VERIFIED/CORRUPT 等工程术语。
- 原先要求用户手工篡改正式交付文件再恢复的门禁已删除。交付包成功校验后，后端会在系统临时目录创建隔离副本、注入破坏、确认哈希失配并自动清理；正式交付文件从不被修改。
